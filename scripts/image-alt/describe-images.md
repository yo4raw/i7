# 画像 alt カタログの描写 sub-agent 指示

あなたは IDOLiSH7 衣装サイト「i7マネ部屋」の alt テキストカタログを作る sub-agent です。`public/assets/` にある 3,527 件の画像（カード 3,376 + 楽曲 151）のうち、担当スライスの全件を日本語 1 文で描写します。

書いた `v` は後から「識別情報（誰のカードか / 誰の楽曲か）+ ここに書いた描写」という 1 本の alt 文字列に合成される（`src/lib/imageAlt.ts`）。識別情報はシートの値が足されるため、`v` に識別情報を足してはいけない。二重になる。

## やること

1. この指示文の末尾に `## 今回の担当` として渡された**担当スライス**を読む。スライスは `scripts/image-alt/build-manifest.mjs` が作った Manifest の切り出しで、1 要素につき 5 フィールドを持つ。フィールドの意味とレコードへの入れ方は次のとおり。
   1. `kind` — `"card"` または `"song"`。レコードの `kind` にそのまま入れる。
   2. `id` — 対象の識別子。レコードの `id` にそのまま入れる。引用符で囲んだ文字列で書く。
   3. `readPath` — **読む画像のパス**。必ずこれを `read` で開く。
   4. `fallbackPath` — 予備のパス。`readPath` が開けないときだけ読む。開けるなら `fallbackPath` は使わない。
   5. `needPrintedName` — `true` のときだけ、絵に印字されたキャラクター名を `n` に控える。`false` のときは `n` を付けない。
   1 レコードはたとえば次の形になる。これは説明のための例で、実際に処理するスライスは `## 今回の担当` にいる。
   ```json
   {"kind":"card","id":"1000","readPath":"tmp/image-alt/scaled/cards/1000.webp","fallbackPath":"public/assets/th_cards/1000.webp","needPrintedName":false}
   ```
2. スライス 1 レコードにつき、`readPath`（開けないときだけ `fallbackPath`）を `read` ツールで実際に開いて、中身を見てから書く。
3. 開けた画像 1 枚につき、描写を 1 レコードにする。
4. 1 枚ぶんの描写を 1 行の JSON にして、`## 今回の担当` の「書き出し先」で指定されたファイルに書き込む。**この指示文には書き出し先を書いていない。** 本番では sub-agent 1 本 1 ファイル、パイロットでは別のパスと、投入ごとに違うので、必ず指定どおりに書く。
5. 全件を書き終えたら、報告は 1 行だけにする。例: `書き終えた: 100 件 / 100 件`。
   1. レコード本文を報告に載せない。`v` の中身、読んだ画像の名前を並べた一覧、数件の引用、集計表。どれも載せない。
   2. レコードの受け渡しはファイルで行う。3,527 件ぶんを戻り文字列で往復させないため。指定のファイルに書いたら報告は「書き終えた」の 1 行だけで止める。

`## 今回の担当` が無ければ、何にも書き出さずにその場で報告して停止する。出力先は自分で推測しない。

## 書き方のルール

1. 1 画像につき 1 レコード。**必ずスライスの全件を書く。** 飛ばさない。複数枚の描写を 1 行にまとめない。
2. `v` は 40〜70 文字の日本語。
3. 書き始めは主語（`〜が` / `〜の`）。助詞から始めない。
4. 描写の順序は 人物 → 服装 → ポーズ・表情 → 背景。
5. **キャラクター名・カード名・レアリティ・属性は `v` に書かない。** 合成段で足すので、ここに混ぜると二重になる。
6. ローマ字・英語は書かない（`n` を除く）。
7. 主観語（`美しい` `かわいい` `かっこいい`）は書かない。
8. 画像に印字されている文字（カード名、ロゴ、看板など）は `v` に拾わなくていい。
9. 1 枚も読めなかった場合は `{"kind":"card","id":"<id>","v":"","note":"判読不能"}` を書き、**それ以上推測しない**。
10. 性別・年齢帯が判断できない場合は断定しない。

上の 10 個を守らないと `scripts/image-alt/validate-visual.mjs` に落とされる。落とされる条件は次のとおり。

1. `v` が 10 文字未満、または 200 文字超。目標の 40〜70 文字そのものは検査されないが、40〜70 文字で書くこと。
2. `v` にキャラクター名の混入。`src/lib/constants.ts` の 16 名すべて、和泉一織 / 二階堂大和 / 和泉三月 / 四葉環 / 逢坂壮五 / 六弥ナギ / 七瀬陸 / 八乙女楽 / 九条天 / 十龍之介 / 百 / 千 / 亥清悠 / 狗丸トウマ / 棗巳波 / 御堂虎於 が 1 文字でも含まれると違反。`百` と `千` だけは一般語彙と衝突するため機械検査から外れているが、キャラ名でもあるので人物の書き換えには使わない。
3. `v` に禁止語を含む。`画像` / `不明` / `TODO` / `placeholder` / `?` / `？` の 6 つ。「カード画像が …」や「表情は不明だ」は落ちる。代わりに「絵」「場面」「見えているもの」と書く。
4. `v` が空。ルール 9 の判読不能レコードを書いて空にした分は再投の対象として ID ごと列挙される。読める画像なら必ず `v` を埋める。
5. `n` が文字列でない、または `n` を `kind: "song"` のレコードに付けた。`n` は `kind: "card"` のときだけ持てる。

主観語は 7 番の例だけでなく、「綺麗」「好感の持てる顔」のような評価も書かない。書くのは目に見える事実だけ（色、形、素材、姿勢、表情、環境）。

人物がいない絵（模様の背景だけ、風景だけ、装飾だけ）は、ルール 3 の主語を絵の主要な被写体に置き換える。人物の代わりにその被写体（背景の模様、建物、楽器など）を主語にすればよく、その場合だけルール 4 の先頭が人物ではなくその被写体になる。性別・年齢帯はルール 10 のとおり、判断できる範囲だけ書いて断定しない。

40〜70 文字は 4 番の 4 要素を短く詰めた長さ。描写を足すより、余分な形容詞と修飾を削る。

## 出力形式

1. 書き出しファイルには **1 行 1 レコード**で書く。Markdown もコードフェンスも添えない。前後に説明文や見出しを混ぜない。
2. 行数は「空行を除いて」スライス件数と一致させる。`scripts/image-alt/merge-visual.mjs` が入口で照合し、数が違うとそこで exit≠0 になる。空行・コメント行・コードフェンス・行末のカンマは入れない。壊れた行は再投の対象になる。
3. フィールドは `kind` / `id` / `v` の 3 つに、`needPrintedName: true` のときだけ `n` を 4 つ目として足す。スライスに無いフィールドを足さない。`kind` と `id` はスライスの値をそのまま使う。
4. `v` は必ず文字列。`n` も必ず文字列で、印字されていたとおりの表記にする。ローマ字で印字されていればローマ字のまま入れる。`needPrintedName: true` でも印字が読み取れなければ `n` は付けない。推測で埋めない。

書き方の例です。実物のスライスから作ったもので、4 例が 3 つの形（`n` 無しのカード / `n` 有りのカード / 楽曲）を示しています。

```json
{"kind":"card","id":"1000","v":"ネオン街を背景に、黒い中国風ジャケット姿の青年が赤い中国結を掲げ、左手を手前に差し出している"}
{"kind":"card","id":"1958","v":"夕暮れの屋上で、スカートの少女が持ったマフラーを風に翻されている","n":"Yuki Aoi"}
{"kind":"card","id":"2519","v":"黒髪の青年が金色の飾り紐が付いた白い軍服に白手袋をはめ、刀の柄を背後へ掲げて身を乗り出している。白い回廊の柱と噴水の水面が背景に見える","n":"IORI IZUMI"}
{"kind":"song","id":"100","v":"7人の青年がサングラスや水着を身に着け、腕を組んだり笑ったりする様子で散らばり、黄色い星形が各写真を囲むように並んでいる"}
```

1. 例 1 — カード。`needPrintedName: false` なので `n` を付けない。
2. 例 2 — カード。シートに行が無いカードなので、`n` に印字名をそのまま入れる。
3. 例 3 — カード。`n` はローマ字で印字されていたのでローマ字のまま入れる。`v` にはローマ字を一切入れていない。
4. 例 4 — 楽曲。`kind: "song"` には `n` を付けない。付ければ検証で落ちる。

例 1 と例 2 は書き出しが場所から入っている（「〜を背景に」「夕暮れの屋上で」）。ルール 3 の「主語で始める」に厳密に当たるのは例 2 の「夕暮れの」型で、場所から始めても検証には引っかからない。書式はルール 3・4（主語で始め、人物 → 服装 → ポーズ・表情 → 背景）を優先する。例 2 は 32 文字で目標より短いので、実際の `v` は 40〜70 文字で書く。

1 枚も読めなかったときは、例 1 と同じ形で `v` を空にして `note` を付ける。`id` は該当画像の `id` に置き換える。

```json
{"kind":"card","id":"<id>","v":"","note":"判読不能"}
```

`v` を空にした `note: "判読不能"` 以外は、推測で `v` を埋めない。読めなかった画像から名前も服装も推測しない。`n` は印字を読めたときだけ入れる。
