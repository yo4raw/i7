# 0025: スコア計算画面に各衣装のスキル上乗せ分布チャートを追加

- 日付: 2026-06-18
- ステータス: 承認

## 背景

スコア計算（デッキ編成）画面には各衣装の数値テーブル（`CardDetailTable`）とモンテカルロのシミュレーション結果（`ScoreCalcResults`）があるが、「いまの編成で各衣装のスキルがどれだけスコアを上乗せし、どれだけ上振れ/下振れし得るか」を一目で比較できない。[0024](0024-card-compare-distribution.md) で衣装比較画面に分布を導入したが、あちらはデッキ非依存（UR 限定・全 Perfect・センタースキル無視）の単体前提で、現在の編成は反映されない。

## 決定

スコア計算画面の `CardDetailTable` と `ScoreCalcResults` の **間** に、現在の編成に基づく各衣装のスキル上乗せ分布チャートを追加する。

- 各衣装のスキル発動成功回数 `K ~ Binomial(n, p)`（`n`=選択曲での最大発動回数, `p`=発動率）を二項分布で**解析的に厳密計算**する。`n` 算出はシミュレーションと同一ロジックを再利用。
- 横軸は **スキル上乗せスコア（0 起点）**。縮小系はカバー秒数。チーム土台は曲線に含めない（土台込み絶対軸だと全曲線が右端に密集するため）。
- 最大 6 枚（センター+メンバー 4+フレンド）を重ね合わせ密度曲線で描画。スコアアップ系と縮小系が混在したら単位が違うため **2 チャートに分割**する。
- 凡例に各衣装の **実効属性値**（特訓・特効・ブローチ・ラビット・センタースキル・ScoreUp アシスト/バッジまでシミュと同じ掛け方で反映）と **チーム内貢献比率** を**数値併記**する。貢献比率の分母は全衣装の実効属性値合計。
- **静的表示**とし、ドラッグしきい値線・スライダー・`P(≥)` 操作・状態永続化は持たない。
- 計算は純粋関数 `src/lib/score/deckSkillDistribution.ts` に切り出し Vitest で単体テストする。描画は新規 `src/components/score/DeckSkillDistribution.svelte`。

## 検討した代替案

- **card-compare の `DistributionChart.svelte` を改造して共用** — ドラッグ前提・絶対軸・4 枚固定の設計を静的・0 起点・6 枚・数値併記へ拡張すると分岐が増え比較画面のリグレッションリスクが上がるため不採用。
- **横軸を絶対スコア（チーム土台込み）** — 比較画面と見た目は揃うが、デッキでは土台が大きくスキルのばらつきが見えないため不採用。
- **モンテカルロからの分布抽出** — 衣装ごとの分解が煩雑で近似かつ低速。二項分布で厳密計算できるため不採用。
- **貢献比率を別チャート（ドーナツ/積み上げバー）化** — 画面要素が増えるため、分布チャート凡例への数値併記に留める。

設計の詳細は [docs/superpowers/specs/2026-06-18-deck-skill-distribution-design.md](../superpowers/specs/2026-06-18-deck-skill-distribution-design.md) を参照。
