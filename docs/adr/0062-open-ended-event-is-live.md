# 0062 終了日が未入力のイベントを実施中として扱う

- ステータス: 承認
- 日付: 2026-08-31

## 文脈

イベント DB (`public/events/events.csv`) はゲームサーバーから毎時 cron で取得している。この CSV には、開始日は入っているが**終了日が未入力**の行が現れる。ゲーム側で終了日が未定のまま開催が始まっているイベントがそれにあたる（例: ID 237「共鳴のアルカソング」は `start_date=2026-07-07` / `end_date=0000-00-00`）。

サイト側の開催判定はすべて `Date.parse(\`${end_date}T17:00:00+09:00\`)` を直接呼んでおり、`0000-00-00` は **NaN** になる。NaN との比較はすべて false になるため、これらのイベントは一律で「終了」に倒れていた。

- イベント一覧・イベント詳細のバッジが「終了」になる
- トップページの「開催中のイベント」に出ない
- `isEventLive()` が false を返すため、**衣装一覧の特効フィルタ・衣装詳細の「現在開催中の特効」・スコア計算の既定イベント選択に乗らない**
- 期間表示が `0000-00-00 17:00` のまま出る

判定ロジックは 5 箇所（`isEventLive` / `EventList.svelte` / `EventStatusBadge.svelte` / `EventCountdown.svelte` / `index.astro`）に重複しており、しかも `isEventLive` だけが開始境界を `00:00 JST`、他は `17:00 JST` として扱う不整合があった。

## 決定

**開始日以降で終了日が未入力のイベントは「終了時刻が未定の実施中イベント」として扱う。**

判定と表示を `src/lib/data/eventPeriod.ts` に集約し、上記 5 箇所はすべてこれを参照する。

| start | end | 状態 |
|---|---|---|
| 未来 | — | `upcoming` |
| 過去 | 未入力（`''` / `0000-00-00` / パース不可） | **`live`** |
| 過去 | 未来 | `live` |
| 過去 | 過去 | `past` |
| パース不可 | — | `past`（判定不能） |

付随して次を決めた。

- **境界時刻は開始・終了とも 17:00 JST に統一する。** UI が一貫して「`start_date` 17:00 〜」と表示している以上、判定もそれに合わせる。結果として開始日当日 0:00〜17:00 は特効が乗らなくなるが、これは表示との整合を取るための意図した変更である。
- **終了未定の表示は「未定」**とし、残り時間は表示しない（算出できないため）。
- **JSON-LD の `endDate` は終了未定なら出力しない。** schema.org/Event で `endDate` は任意であり、`0000-00-00T17:00:00+09:00` のような不正値を構造化データに出すより省略するほうが正しい。
- **`fetchEventsCsv` の行フィルタから `end_date` 必須条件を外す。** `0000-00-00` は truthy なので現状は通過しているが、終了日が完全に空の行も同じ意味として残す必要がある。`start_date` は判定の起点なので必須のまま。

## 代替案

- **CSV 取り込み時に終了日を遠い未来の日付で埋める** — 判定側は無変更で済むが、「未定」と「その日付まで開催」を区別できなくなり、期間表示に架空の終了日が出る。取り込んだ生データを書き換える点も、他の cron 取り込みの方針（取得したものをそのまま置く）と合わない。
- **終了日未入力の行を取り込み時に除外する** — 実際に開催中のイベントの特効情報が丸ごと落ちる。利用者にとって最も価値がある「今の特効」が出なくなるため採らない。
- **各コンポーネントの NaN 判定だけをその場で直す** — 5 箇所すべてに同じ分岐が増え、開始境界の不整合も残る。同じバグを次の箇所で再発させる。
