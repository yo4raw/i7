# 0013. 楽曲詳細のノーツ内訳で白ノーツ／色ノーツを分離表示する

- ステータス: 承認
- 日付: 2026-06-15

## 背景

楽曲詳細ページの「ノーツ内訳」(ADR 0009) は、ステージ×属性のセルで白ノーツ(始点)と色ノーツ(終点)を合算した数値だけを表示していた。白と色は 1 ノーツあたりのスコア係数が異なる（白 ×0.025 / 色 ×0.03）ため、合算値だけでは色ノーツの多寡が読めず、スコアの内訳が把握しづらかった。

## 決定

ノーツ内訳テーブルの各セルを「白 / 色」の形式に変更し、白ノーツ数と色ノーツ数を分離して表示する。

- ステージ別・属性別の各セルで `{白} / {色}`（左=白・右=色）を表示する
- 色ノーツ（右）を `font-semibold` で強調し、係数が高い側を視覚的に区別する
- 各属性ヘッダー下に小さく `白 / 色` のサブラベルを付け、テーブル下に「左=白ノーツ（×0.025）/ 右=色ノーツ（×0.03）」の注釈を添える
- 合計行も同じく白/色を分離する
- 3 列（Shout/Beat/Melody）構成と PC 横並びレイアウト (ADR 0011) は維持する

データ層 `buildNoteBreakdown` は白+色合算をやめ、`NoteBreakdownRow` / `totals` を属性×白/色の 6 値で返すよう変更する。

## 検討した代替案

- **6 列に分割（Shout白・Shout色・…）**: 最も明確だが PC でも横長になりモバイルで横スクロール必須。情報密度より可読性を優先しセル内分割を採用。
- **セル内で白を上・色を下の 2 段**: 行高が倍増し縦に冗長。横並び `白 / 色` の方がコンパクト。
- **全体の白/色合計のみを別表で追加**: ステージ別の分布が見えず、ノーツ内訳の目的（ステージ別把握）に合わない。

## 影響

- 変更は `src/lib/songNoteBreakdown.ts`（集計ロジック）と `src/pages/songs/[id].astro`（表示）、`tests/unit/songNoteBreakdown.test.ts`（契約更新）。
- `buildNoteBreakdown` の利用箇所は `songs/[id].astro` のみで、戻り値型の変更による波及は同ページに閉じる。
