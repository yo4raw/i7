# 0029: 編成組合計算で過去のハイスコアイベントを選択可能にする

- 日付: 2026-06-23
- ステータス: 承認

## 背景

編成組合計算（`/score-calc/max-score-finder/`）は `isEventLive` で判定した **現在開催中のイベント** の金/銀特効 UR 衣装しか探索対象にできなかった（`buildLiveTierMap` を使用）。開催中イベントが無い期間や、過去のハイスコアイベントを振り返って理論値最大編成を検討するケースに対応できなかった。

衣装比較画面（ADR 0026）には既にハイスコアイベントを選択して特効を反映する UI・永続化パターンがあり、これを編成組合計算にも適用できる。

## 決定

編成組合計算に **ハイスコアイベントを選択するドロップダウン** を設け、選択したイベント単体の金/銀特効 UR 衣装を探索対象とする。

- 候補は **ハイスコアイベントのみ**（`isHighScoreEvent()` で判定）、**新しい順**（`start_date` 降順）。ラベルはイベント名＋開始日。開催中は「【開催中】」を前置する。
- **開催中のハイスコアイベントがあれば既定選択**（複数なら最新）。無ければ最新のハイスコアイベント。
- ティアマップは日付非依存の `buildTierMapForEvent`（`src/lib/data/eventBonusTiers.ts`）を使い、過去イベントの金/銀/銅を正しく再現する。
- 選択は編成組合計算専用の **localStorage（`i7_max_finder_event_id`）に保持**し、衣装比較（`i7_compare_event_id`）とは独立させる。再読み込み後も復元する。
- ハイスコアイベントが0件のときはドロップダウンを表示せず空状態メッセージを出す。

## 検討した代替案

- **ポイント/ミッション系も含む全イベントを選択対象にする** — 編成組合計算は理論値最大編成（ハイスコアライブのスコアリング）が目的で、ポイント系の特効は趣旨が異なり選択肢が冗長になる。ハイスコアイベントのみとした。
- **衣装比較と同じ `i7_compare_event_id` を共用** — 2画面は用途（比較 vs 編成探索）が異なり、片方の選択がもう片方を勝手に変えると驚きがある。専用キーで独立させた。
- **永続化しない（毎回開催中/最新を既定選択）** — 過去イベントを繰り返し検討する際に毎回選び直す手間が生じる。永続化を採用した。

設計の詳細は [docs/superpowers/specs/2026-06-23-max-finder-event-select-design.md](../superpowers/specs/2026-06-23-max-finder-event-select-design.md) を参照。
