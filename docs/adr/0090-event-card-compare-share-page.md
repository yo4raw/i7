# 0090: 衣装比較の共有ページをイベント配下へ移し、対象楽曲ぶんを一括で画像化する

- 日付: 2026-09-19
- ステータス: 承認

## 背景

衣装比較の SNS 共有ページは ADR 0074 で `/card-compare/share/` に置いた。イベント配下に置かなかった理由は、当時イベント対象楽曲がグローバルな 1 配列（曲選択の先頭ピン留め用）しかなく、過去イベントのページが現行イベントの曲を表示してしまうためだった。

その後 ADR 0081 で対象楽曲は `event-songs.json` の `byEvent` にイベント単位で持つようになり、イベント詳細の対象楽曲セクションと `/events/{id}/share/songs/`（ADR 0084）がそれを使っている。ADR 0074 が置き場所を決めた前提は既に崩れている。

運用面では、イベントごとに対象楽曲 7 曲前後の衣装比較画像を SNS に貼っており、現行ページでは曲セレクトを切り替えて 1 枚ずつ保存する手間がかかっていた。

## 決定

`/card-compare/share/` を **`/events/{id}/share/card-compare/` へ移動**し、そのイベントの対象楽曲ぶんのパネルを縦に並べて **一括ダウンロード**できるようにする。旧 URL のページは削除する（`noindex` で検索流入がなく、リダイレクトは置かない）。

- 生成対象は `byEvent` に曲が登録されたイベントだけ（`/share/songs/` と同じ規則）
- 特効はページのイベント自身に固定し、セレクトは置かない。ハイスコアイベント（`isHighScoreEvent`）でなければ「特効なし」で計算する。衣装比較の特効セレクトが列挙するのがハイスコアイベントだけなのと揃える
- 曲ごとに 1 枚。パネルの中身（スコアアップ Top10 + 判定縮小 Top10・UR 全着・1024px 固定・`compact` チャート）は ADR 0074 の決定 2〜4 のまま
- ヘッダー帯はイベント名を主見出しにし、その横に `衣装比較 Top10 1/7` のページ番号を出す（ADR 0083 / 0089 と同じ見せ方）。曲名・難易度・秒数・ノーツ数・母集団・特効の有無は 2 行目に出す
- 一括ダウンロードは `EventShareImage` の `panels` 経路を使う。ファイル名は `{ID}_{イベント名}_衣装比較Top10_1.png` …
- ビルド時に埋め込む衣装データは UR だけに絞る（母集団が UR 全着のため。全レアリティを埋め込むとイベントページ 1 枚あたり 2.3MB になる）。クライアント側の自動リフレッシュは従来どおり行う
- 衣装比較ページの「この結果を画像で共有」リンクは、`event-songs.json` の `currentEventId` のイベントのページへ向ける。対象楽曲が未登録ならリンクを出さない
- `noindex` + sitemap 除外は `/events/\d+/share/` の既存パターンに含まれる。`/card-compare/share/` 専用の除外は削除する

ADR 0074 の決定 1（配置）は本 ADR で上書きする。決定 2〜4 は有効。

## 検討した代替案

- **現行ページを残し、イベント配下に別ページを足す** — 同じパネルを持つコンポーネントが 2 系統になり、チャートの見た目を変えるたびに両方を直すことになる。曲を自由に選びたい用途は衣装比較本体で足りるため、移動にする
- **旧 URL からリダイレクトを置く** — `noindex` で検索結果に出ておらず、UI からのリンクも差し替えるため、恒久的な設定を増やす価値がない
- **1 枚に複数曲をまとめる** — 1 曲ぶんが 1024×1073 のほぼ正方形で、2 曲重ねると縮小表示で棒グラフが読めない。ADR 0074 の「スコアアップと判定縮小を別画像にしない」を保ったまま曲を足すには 1 曲 1 枚しかない
- **全レアリティを埋め込む** — 共有ページで使わない SSR 以下を 40 ページ超に重複して埋め込むことになる。UR 以外は計算の入力にならないため絞る
