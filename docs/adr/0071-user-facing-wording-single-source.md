# 0071 ユーザー可視テキストの表記を CLAUDE.md の表で一元管理する（ToolGuide の共通化と用語集の追加は見送り）

- ステータス: 承認
- 日付: 2026-09-03

## 文脈

サイト上のユーザー可視テキストを対象に、静的解析（禁止語・翻訳調・文長・語彙多様性）と、構造・読みやすさ・ガイド型照合の 3 観点でレビューした。禁止語と翻訳調の検出はほぼゼロだった一方、次の 2 種類の問題が見つかった。

1 つは実挙動との食い違いで、13 件あった。ADR 0058 は「解説の内容はツールの実挙動を説明するものに限る」「ツールの仕様を変えたときはここも必ず更新する」と定めているが、その後の実装変更に解説が追随していなかった。とくに「衣装比較でレアリティ・属性・キャラクターで絞り込める」「ポイント芸計算で獲得pt表が表示される」「スコア計算で共通ブローチが自動割り当てされる」の 3 件は存在しない機能を案内しており、利用者が探しても見つからない。`MaxScoreFinder` の「SCOREUP アシスト +12%」は実装（`SCOREUP_ASSIST_RATE = 0.2`）と数値そのものが違っていた。

もう 1 つは表記の不統一で、同じものが 2 通りの名前で呼ばれていた。「固定ブローチ」と「固有ブローチ」、「並べ替え」と「並び替え」、「割当」と「割り当て」が該当する。とくに衣装比較は UI ラベルが「並び替え」、同じ画面の解説が「並べ替え」で、1 画面の中で割れていた。`MaxScoreFinder` のチェックボックス説明に至っては一文の中に「割り当てる」「自動割当します」「割当」が同居していた。

## 決定

### 1. ユーザー可視テキストの表記は CLAUDE.md の表を単一の情報源とする

`CLAUDE.md` の「用語ポリシー」に、使う表記と使わない表記を対にした表を置く。新規 UI・解説文を書くときはこの表に従う。

表記ゆれは、書き手が都度選ぶ限り必ず再発する。既存の用語ポリシーは「カード → 衣装」「共有ブローチ → 共通ブローチ」の 2 件を散文で書いていたが、増えるたびに散文が伸びると参照しづらい。表であれば追記も参照も一手で済み、レビュー時の照合対象としても使える。

ADR ではなく `CLAUDE.md` に置くのは、これが「都度参照される規約」であって「一度きりの意思決定」ではないためである。ADR は決定の経緯を残し、規約本体は `CLAUDE.md` が持つ。

### 2. ToolGuide の免責文を共通フッターへ括り出す案は却下する

4 つのツール解説のうち 3 つで、`notes` の末尾が「算出値は有志による計測・推定に基づくもので、ゲーム内の挙動と完全に一致することを保証するものではありません。」という同一文で終わっていた。同じ文の 3 回反復であり、`ToolGuide.astro` 側に共通フッターとして 1 回だけ出す案を検討した。

却下する。ポイント芸計算の免責には「実際に走らせる前に、少ない回数で数値が合うか確認することを勧めます」という固有の追記があり、共通化すると失われる。ツールごとに推定の性質と読者に促したい確認が違うため、免責は各ページが自分の言葉で持つほうが正しい。

そのうえで、唯一この但し書きを欠いていた編成組合計算に同じ文を追加した。4 ツール中もっとも計算が重く推定の積み重ねが大きく、かつ「総当たりで全ての組合せを評価する」と最も強く断言するページで免責が抜けているのは、機械的なコピーの結果として最も悪い形だった。

### 3. ToolGuide への用語集と問い合わせ導線の追加は見送る

ガイド型文書の必須要素として、用語集（「特効」「判定縮小」「カバー率」等の定義）と、解説で解決しない疑問の持ち込み先が欠けている。

見送る。用語はサイト全体で共通のため、4 ページそれぞれに定義を置くと重複し、変更時にずれる。置くなら仕様解説ページか専用ページを単一の情報源にすべきで、ツールページ側はそこへのリンクを持つ形になる。問い合わせ導線も同様に、トップと about が既に持っている窓口へのリンクで足りる。いずれも本レビューの範囲（既存テキストの是正）を超える追加であり、別途扱う。

### 4. steps を 4 項目に揃えている点は変更しない

4 つのツール解説がいずれも `steps` を 4 項目で構成しており、同じ鋳型の反復にあたるとの指摘があった。

変更しない。4 ツールとも実際の操作が 4 段階（対象を選ぶ → 前提を決める → 条件を設定する → 実行・確認する）であり、手順の数は内容が持っている構造である。並列な手順を並列に書くのは正しく、鋳型を崩すために手順を分割・結合すると操作の実態から離れる。

## 検討した代替案

**表記ゆれを lint やテストで機械的に検出する**: 禁止語リストとして CI で落とす案を検討した。却下する。「割当」は内部識別子（`broachAssignment.ts`）では正しく、ユーザー可視テキストとコードを機械的に切り分けられない。誤検知を抑える例外リストの保守が、防ぎたい問題より重くなる。

**トップページの免責・プライバシー・謝辞・お問い合わせを about へ集約する**: トップと about でこの 4 節がほぼ同文で二重掲載されており、節の並び順も逆で、指示語だけが「上記」「下記」に分岐している。集約すべきだが、両ページとも `sitemap.filter` の対象でインデックスされるため（ADR 0057）、片方の本文を大きく削るのは SEO への影響を伴う。本 ADR の範囲外とし、別途判断する。
