# 0020: ダークモードの廃止（段階的）

- 日付: 2026-06-15
- ステータス: 承認

## 背景

ダークモードを廃止する。新規コンポーネントごとに `dark:` バリアントをペアで書く保守負担があり、サイトの表示はライト固定に一本化する方針となった。

## 決定

ダークモードを廃止し、**2段階**で実施する。

- **段階1（本 ADR で着手・別 PR）— 無効化（ライト固定）**: サイト暗転の起点である `<html>` の `.dark` クラスを一切付与しない。具体的には `BaseLayout.astro` の FOUC 防止インラインスクリプト（`i7_theme_mode` / `prefers-color-scheme` で `.dark` を付与）を削除し、`FooterTools.svelte` のテーマ切替トグルと `i7_theme_mode` 書き込みを削除。`theme-color` メタはライト用1つに集約。各 `dark:` クラスは残るが `.dark` が付かないため発火せず、常にライト表示になる
- **段階2（後続の別 PR）— 完全除去**: 全コンポーネント/ページの `dark:` クラス、`global.css` の `@custom-variant dark` / `html.dark` ルール / チャート用 CSS 変数のライト/ダーク切替、`STORAGE_KEYS.THEME_MODE`、`EventShareImage.svelte` の dark 分岐、CLAUDE.md のダークモード規約をすべて削除する

段階分けの理由: 段階1は数ファイルの低リスク変更で即座にユーザー影響（ダークモード提供）を停止できる。段階2は45ファイル・数百箇所の機械的削除で見落としリスクがあるため、ライト固定を確定させた上で別 PR で安全に実施する。

## 検討した代替案

- **一括で完全除去（段階1を省略）** — 大規模な機械的差分を一度に行うと検証負荷・見落としリスクが高いため、段階分けを採用
- **ダークモードを維持** — 保守負担とライト一本化の方針により不採用

段階1の詳細は [docs/superpowers/specs/2026-06-15-dark-mode-disable-design.md](../superpowers/specs/2026-06-15-dark-mode-disable-design.md) を参照。
