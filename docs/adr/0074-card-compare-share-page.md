# 0074 衣装比較の結果を画像で共有するページを追加する

- ステータス: 承認
- 日付: 2026-09-03

## 文脈

イベント詳細には `/events/{id}/share/ur/` `/events/{id}/share/ssr/` という SNS 共有ページがあり、特効衣装をまとめた固定幅パネルを `modern-screenshot` で PNG 化して手動で貼る運用になっている（ADR 0006）。

同じことを衣装比較でもやりたい、という要望が出た。イベント対象曲ごとに「スコアアップで強い衣装」「判定縮小で強い衣装」の上位を、グラフ付きで 1 枚の画像にして共有したい。対象は所持衣装に限らず UR 全着とする。

置き場所の候補としてまずイベント配下（`/events/{id}/share/songs/`）が挙がったが、調査の結果**イベント対象楽曲はイベント単位で持っていない**ことが分かった。`src/data/event-songs.json` の `eventSongIds` は「曲選択ドロップダウンの先頭にピン留めする曲」を表すグローバルな 1 配列であり（ADR 0021）、`EventRow`（`fetchEventsCsv.ts`）に楽曲フィールドはない。イベント配下に置くと、過去イベントのページが現行イベントの曲を表示してしまう。

## 決定

### 1. 衣装比較の配下に共有ページを置く

`/card-compare/share/` を追加する。イベント配下には置かない。

曲は既存の `SongSelect` で選ぶ。`SongSelect` はイベント対象楽曲を先頭グループにピン留めし先頭を既定選択するため、「イベント対象曲ごとに見る」という要望はデータ構造を変えずに満たせる。過去イベントとの整合が崩れる問題も起きない。

対象曲をイベント ID ごとに持つようデータ構造を拡張する案も検討したが、過去イベント分の入力が必要になるうえ、得られるのは URL の見栄えだけで、共有画像の中身は変わらないため見送った。

ADR 0057 の方針に従い、ページは `noindex,follow` とし `astro.config.mjs` の `sitemap.filter` からも除外する。衣装比較の派生であり独自性がないため。

### 2. 1 枚のパネルにスコアアップ・判定縮小の両方を載せる

衣装比較本体はタブで切り替えるが、共有パネルはタブを持たず両方を縦に並べる。SNS には画像 1 枚を貼るのが前提であり、2 枚に分けると受け手が片方しか見ない。

並び順は衣装比較の既定と揃える（スコアアップ = 期待スコア合計の降順 / 判定縮小 = 属性値由来スコアの降順）。共有パネルに並び替え UI は置かない。画像として固定した基準で比較できることを優先する。

母集団は UR 全着とし、所持による絞り込みはしない。共有画像は誰が見ても同じ内容であるべきで、送り手の所持状況に依存させない。

特効イベントの初期選択は衣装比較が保存している `i7_compare_event_id` を読む。ただし共有ページ側での変更は保存しない。比較画面の選択を共有ページの操作で書き換えないため。

### 3. チャートは新規に作らず既存へ `compact` を足す

`ScoreUpChart.svelte` / `ShrinkChart.svelte` に `compact` を追加し、共有パネルからはこれを立てて使う。共有用の別チャートは作らない。積み方・配色・凡例が衣装比較と食い違うと、同じ数字を指しているのに別物に見えるため。

`compact` での差分は表示に限る:

- 横スクロールとタップ選択を無効化する（画像に写らない操作を残さない）
- 列幅を広げ、サムネイルを 48px から 80px にする
- スコアアップのスキル種別行を省く。「スコアアップ（タイマー）」のような長いラベルが折り返して列の高さと特効バッジの位置が不揃いになるため。種別はセクション見出しで判別できる
- 判定縮小のカバー秒数の併記と、凡例のうち並び順の記述を省く。並び順はセクション見出しに出る

計算そのものは `cardStrength.ts` をそのまま使う。共有ページ専用の計算は持たない。

### 4. パネル幅は 1024px 固定

端末によらず同じ画像になるよう幅を固定する。狭い画面では親を横スクロールさせる（イベント共有パネルと同じ扱い）。

当初はイベント共有パネルと同じ 640px で設計したが、その幅では 10 列に詰めるとサムネイルが 48px までしか取れず、どの衣装か判別しづらかった。衣装の絵柄は共有画像の主役であるため、幅を 1024px へ広げてサムネイルを 80px とする。10 列 × 96px + 余白で 996px となり 1024px に収まる。生成される画像は約 1024 × 1073 のほぼ正方形になる。

## 検討した代替案

- **イベント配下に置き、グローバルの `eventSongIds` を使う** — 開催中は自然だが、過去イベントのページが現行イベントの曲を表示する。実態とズレたページを恒久的に残すため不採用
- **曲ごとにパネルを縦に全件並べる** — 一覧性は上がるが、1 画面で UR 全着 × 曲数を計算することになり、共有したい 1 曲以外は無駄になるため不採用
- **スコアアップと判定縮小を別画像にする** — 受け手が片方しか見ないため不採用
- **640px のまま 5 列 × 2 段に折り返す** — サムネイルは大きくできるが、10 着の棒の高さを一目で比較できなくなるため不採用
