# 0021: 楽曲許可リストを「イベント対象楽曲」のピン留めに転換

- 日付: 2026-06-16
- ステータス: 承認

## 背景

`src/data/allowed-songs.json` の `allowedIds` は「この ID の楽曲のみ表示する」グローバル許可リストとして運用していた（ADR なしで導入）。開催中イベントの対象楽曲を登録したところ、楽曲一覧・スコア計算・衣装比較・ホームのすべてがその数曲だけに絞り込まれ、他の曲を選べなくなる副作用が大きかった。

求めていたのは「絞り込み」ではなく、曲選択ドロップダウンで**イベント対象楽曲を先頭に出して選びやすくする**こと。

## 決定

許可リストによる絞り込みを**全廃**し、イベント対象楽曲を曲選択の**先頭グループにピン留め**する方式へ転換する。

- データ: `allowed-songs.json` → **`event-songs.json`**、キー `allowedIds` → **`eventSongIds`**（配列順が表示順、先頭が既定選択）にリネーム。意味を「表示許可」から「イベント対象（先頭表示）」に変更
- `filterAllowedSongs` を削除し、全ページ・全コンポーネントで楽曲を全件表示に戻す。代わりに `getEventSongIds()` / `firstEventSongId()` を追加
- 曲選択ドロップダウンを共通コンポーネント **`SongSelect.svelte`** に集約。optgroup 順は `イベント対象楽曲` → `選択中の曲` → `カテゴリ別`。スコア計算・編成組合計算・衣装比較の3か所が利用
- 初期選択はイベント対象楽曲の先頭（スコア計算は `i7_score_calc_state` の復元を優先）

## 検討した代替案

- **許可リストのまま運用** — 全画面が数曲に絞られ他の曲を選べず、ユーザー要望（全曲から選べて対象曲が目立つ）と矛盾するため不採用
- **共通化せず各 select に個別対応** — 同じグルーピングロジックが3か所に重複し保守性が低いため不採用
- **データ名 `allowedIds` を流用** — 「allowed なのに全曲表示」と名前と実態が乖離し紛らわしいためリネームを採用
