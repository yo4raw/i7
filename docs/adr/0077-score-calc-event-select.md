# 0077 スコア計算で対象イベントを選んで特効を反映する

- ステータス: 承認
- 日付: 2026-09-06

## 文脈

スコア計算ページは、衣装をスロットに置いた時点で特効段階（金/銀/銅）を自動で入れる。ただしその元になる特効マップは **開催中のイベントだけ** から作っていた。開催中のハイスコアイベントがない期間は常に「特効なし」で入り、次のイベントに向けた試算や過去イベントの振り返りでは 6 スロットぶん手で段階を選ぶ必要があった。

一方、衣装比較（[0026](0026-card-compare-event-bonus-select.md)）と編成組合計算には「対象イベント」セレクトがあり、過去のハイスコアイベントも選んで特効を反映できる。同じサイト内で片方のツールだけ選べないのは利用者にとって分かりにくい。

## 決定

**スコア計算ページにも「対象イベント」セレクトを置き、選んだイベントの金/銀/銅を衣装配置時の既定段階にする。**

- 一覧は編成組合計算・衣装比較と同じく **ハイスコアライブイベントのみ**を新しい順に並べる。特効の倍率（100/120/140%）はハイスコアイベントの属性値ボーナスを表しており、ポイント系イベントの特効（ポイント倍率）にはそのまま当てはまらないため
- 先頭に「特効なし（イベントを選ばない）」を置く。既定は開催中のハイスコアイベント、なければ「特効なし」。これは従来の挙動（開催中のみ反映）と同じ結果になる
- **イベントを切り替えた瞬間に、配置済み 6 スロットの段階も選び直したイベントで上書きする。** 手で変えた段階も上書きされるが、対象イベントを選び直す操作は「このイベントの特効で計算し直したい」という意思表示であり、古い段階が残る方が誤りに気づきにくい。切替後のスロットごとの手動変更は従来どおりできる
- 選択イベント ID は既存のスコア計算状態（`i7_score_calc_state`）に 1 フィールド追加して保存する。新しい localStorage キーは増やさない。保存デッキにも同じ状態が入るため、読込時にイベントも戻る。共有 URL は段階そのものを持っているので変更しない
- 保存された ID が一覧にない（旧データや CSV から消えた）ときは「特効なし」扱い。ID が保存されていない旧データや共有 URL からの復元では選択を変えない

## 検討した代替案

### イベント一覧にポイント系イベントも含める（却下）

特効を持つイベントはすべて選べる方が網羅的だが、ポイントイベントの特効はスコアではなくポイントに効く。スコア計算に載せると倍率の意味が食い違う。編成組合計算・衣装比較とも揃わない。

### イベント切替時に配置済みスロットの段階を変えない（却下）

手動で選んだ段階を守れるが、イベントを選び直したのに古い特効で計算が続く。ページの上部で選び直したことと、スロットの小さなセレクトの値が食い違っていることに気づきにくい。

### 選択イベントを専用の localStorage キーに保存する（見送り）

衣装比較・編成組合計算はそれぞれ専用キーを持つ。スコア計算は既に画面状態を丸ごと 1 キーで保存・復元しており、そこに載せる方がバックアップ対象の追記も不要で、保存デッキにも自然に含まれる。

### 衣装選択モーダルにも特効バッジや「特効のみ」絞り込みを出す（見送り）

選択時に特効衣装を見つけやすくなるが、モーダルへイベント情報を渡す改修が増える。まずセレクトとスロット反映だけで様子を見る。

## 影響

- `ScoreCalc.svelte` に対象イベントのセクションが 1 つ増え、特効マップの元が「開催中イベント」から「選択イベント」に変わる
- スコア計算ページの ToolGuide の手順 3 の文言を更新する
- E2E（`tests/score-calc-persistence.test.ts`）に、過去イベント選択時の段階反映・切替時の選び直し・リロード後の復元を追加する
