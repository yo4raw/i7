# 0091: グループ記念日イベントのメンバー衣装を銅特効として扱う

- 日付: 2026-09-19
- ステータス: 承認

## 背景

グループ記念日イベント（IDOLiSH7 / TRIGGER / Re:vale / ŹOOĻ の各記念日）は、金・銀特効に個別の衣装を挙げたうえで、銅特効を「そのグループのメンバーの衣装すべて」としている。イベント DB の CSV ではこれを `special3_member` 列（例: `TRIGGER`）で表し、銅特効の衣装 ID 列は空になっている。年によっては銅特効の ID を全件列挙した行もあり（2026 年の Re:vale / IDOLiSH7 / ŹOOĻ）、その内容は「グループのメンバー衣装のうち金銀に入っていないもの + グループ衣装」とほぼ一致する。

本サイトの特効判定は衣装 ID の列だけを見ていたため、`special3_member` 方式の記念日（直近では TRIGGER記念日2026）では、メンバーの衣装が特効なしとして計算されていた。スコア計算・衣装比較・編成組合計算・衣装一覧の特効バッジ・イベント詳細の銅特効一覧・衣装詳細の開催中特効がすべて影響を受ける。

## 決定

`special3_member` に挙がったグループ／キャラクターの衣装を、**金・銀に入っていなければ銅特効として扱う**。判定は特効ティアマップを作る 1 か所（`buildTierMapForEvent`）で行い、各計算はそのマップを参照するだけにする。

- 衣装の一致条件は「キャラクター名がメンバー名に一致する」または「グループ名がメンバー名に一致する」。グループ衣装（`name` が `TRIGGER` 等）はキャラクター名側の一致で拾う
- 金・銀の指定は上書きしない（既存の金 > 銀 > 銅の優先はそのまま）
- 衣装 ID の列と `special3_member` の両方がある行は和集合にする
- `special3_member` はグループ記念日以外にも 2 キャラ指定のポイントライブイベント（Sugao / 吉兆の調べ / BUDDY NIGHT NARRATIVE）で使われている。同じ列・同じ意味なので区別せず同じ扱いにする。ハイスコア計算はこれらのイベントを対象にしないため、影響は衣装一覧のバッジと詳細ページに限られる
- 表記ゆれ（`ZOOL` / `ŹOOĻ`）や合同衣装（`百＆千` 等）の名寄せは行わない。メンバーの個人衣装はグループ名の一致で拾えるため、取りこぼすのはグループ衣装・合同衣装のごく一部に限られる。必要になったら正規化を足す
- 衣装候補は変えない。編成組合計算の探索候補は引き続き金・銀の UR 衣装だけとする（銅 2.0 倍の衣装が最適解に入る余地は小さく、探索空間を数倍にする価値がない）

## 検討した代替案

- **CSV 取り込み時（ビルド時）に銅特効の ID 列へ展開する** — 衣装データはクライアントで自動リフレッシュされるため、ビルド後に追加された新衣装が銅から漏れる。ティアマップを作る時点で手元の衣装リストと照合するほうが常に最新になる
- **イベント名に「記念日」を含む行だけを対象にする** — データの意味は `special3_member` 列が担っており、名前判定は不要な二重条件になる。列があるイベントはすべて同じ意味なので列だけを見る
- **CSV 側で銅特効 ID を全件列挙してもらう** — 上流（ゲームサーバーの DB）の運用に依存し、衣装追加のたびに追記が必要になる。本サイト側で解釈するほうが確実
