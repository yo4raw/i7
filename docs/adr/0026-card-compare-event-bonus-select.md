# 0026: 衣装比較のイベント特効反映をハイスコアイベント選択式へ変更

- 日付: 2026-06-21
- ステータス: 承認

## 背景

衣装比較画面（`/card-compare/`）の特効反映は「イベント特効を反映」チェックボックス1つで、ON にすると **開催中イベント全体をマージした特効**（`buildLiveTierMap`）を自動適用していた。任意のイベントを選べないため、過去・今後のハイスコアイベントの特効を当てた比較ができず、また開催中に複数イベントがあると特効がマージされ、特定イベント単体での比較ができなかった。

## 決定

衣装比較画面に **ハイスコアイベントを選択するドロップダウン** を設け、選択したイベント単体の特効（金/銀/銅 → 倍率）を比較結果に反映する。

- 候補は **ハイスコアイベント全件**（過去・開催中・今後すべて。`isHighScoreEvent()` で判定）、**新しい順**（`start_date` 降順）。ラベルはイベント名のみ。
- **開催中のハイスコアイベントがあれば既定選択**（複数なら最新）。無ければ「特効なし」。
- 既存のチェックボックスは廃止し、ドロップダウンに統合する。先頭が「特効なし」。
- 選択は **localStorage（`i7_compare_event_id`）に保持**し、再読み込み後も復元する。
- ハイスコアイベントが0件のときはドロップダウンを表示せず特効なし固定とする。
- 単一イベント用ティアマップ生成を純関数 `buildTierMapForEvent`（`src/lib/data/eventBonusTiers.ts`）に切り出し、`buildLiveTierMap` はその再利用形にリファクタする。`toEventForBonus` に `eventtype` を追加してクライアントへ渡す。

## 検討した代替案

- **チェックボックス＋ドロップダウン併存** — ON/OFF とイベント選択で状態が二重になり複雑。ドロップダウン先頭の「特効なし」で OFF を表現できるため不採用。
- **全イベントタイプを選択対象にする** — 特効のないイベントが大量に並び選びにくい。比較の目的はハイスコアイベントの特効なので不採用。
- **全ハイスコアイベントのティアマップを事前計算してキャッシュ** — 選択は常に1つで、都度生成のコストは無視できるため不採用。
- **スロット個別の特効手動上書き（スコア計算画面方式）** — 比較は一覧の相対評価が目的で、衣装ごとの上書きは過剰。選択イベントの特効を一律反映する方針とした。

設計の詳細は [docs/superpowers/specs/2026-06-21-compare-event-bonus-select-design.md](../superpowers/specs/2026-06-21-compare-event-bonus-select-design.md) を参照。
