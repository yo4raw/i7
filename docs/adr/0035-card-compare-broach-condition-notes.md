# 0035: 衣装比較で全属性編成ブローチを加算し条件付きブローチの前提を注記する

- 日付: 2026-06-30
- ステータス: 承認

## 背景

衣装比較ページ（[0007](0007-card-compare-page.md)）は各衣装を 1 枚だけの擬似デッキ `[card, null×5]` で評価し、固有ブローチを 1 個ずつ装備したときに属性値由来スコアが最大になるものを採用する（`calcCardStrengthAppeal`）。

このため**デッキ構成に依存する条件**を持つブローチのうち、種類7「全属性編成」（デッキに Shout / Beat / Melody の 3 属性すべてが存在することが条件）は、1 枚デッキでは `hasAllAttributes` が必ず false になり**発動扱いにならず属性値が加算されない**。実プレイでは全属性を含むデッキを組めば必ず発動できるため、比較の「ベストケース・固有ブローチ装備込み」という前提（cardStrength.ts ヘッダ）と矛盾し、種類7ブローチを持つ衣装が不当に低く見えていた。

一方で、種類4（グループ指定）・種類5（アイドル属性指定）・種類9（楽曲スコアアップ）など条件付きで加算されるブローチは、比較表に属性値・スコアとして反映されるものの**どの前提で発動しているのかが画面から読み取れない**という課題もあった。

## 決定

1. **種類7「全属性編成」を衣装比較で発動扱いにして属性値を加算する。** `resolveDeckBroachs` にオプション引数 `assumeAllAttributes` を追加し、`true` のとき種類7の条件判定を `hasAllAttributes` に依らず常に成立させる。`calcCardStrengthAppeal`（比較専用）だけがこれを渡す。スコア計算ページ・編成組合計算は引数を渡さず、従来どおり実デッキの属性構成で判定する（挙動不変）。

2. **採用したブローチを `CardStrengthEntry` に保持する。** `calcCardStrengthAppeal` の戻り値に採用ブローチ（`appliedBroach: FixedBroach | null`、ブローチ無しが最良の場合は null）を加える。

3. **条件付きブローチの前提を詳細パネルに注記する。** 採用ブローチの種類から前提文を引く対応表を設け、詳細パネルに「ブローチ前提」行を追加する。

   | 種類 | 前提注記 |
   |------|----------|
   | 4 グループ指定 | 同グループ編成が前提 |
   | 5 アイドル属性指定 | 同アイドル・同属性編成が前提（比較では 1 枚分のみ加算） |
   | 7 全属性編成 | 全属性編成が前提 |
   | 9 スコアアップ | 対象楽曲でのみ発動 |
   | 1 / 6（無条件）・ブローチ無し | 注記なし（`-`） |

4. **メインのチャート一覧（多数のバー）には注記を出さない。** バーごとに文字を足すと過密になるため、前提注記は選択中（最大 4 枚）の詳細パネルに限る。

## 検討した代替案

- **cardStrength 内で種類7だけ手計算で属性値を加算** — `resolveDeckBroachs` の発動上限（limit）・倍率ロジックと二重管理になり却下。
- **全属性を満たすダミーカードで擬似デッキを埋める** — 種類4（同グループ判定）・種類5（同アイドル判定）の条件を壊すため却下。オプション引数による種類7限定の発動が最も影響範囲が狭い。
- **注記文に `condition` フィールドをそのまま使う** — 値が「アイドル属性指定カウント」等の種類ラベル寄りでユーザー向けの前提文として硬いため、種類→前提文の対応表を用いる。
- **種類5の倍率を比較でもデッキ最大（5 枚）まで見込む** — 比較は 1 枚評価のため過大表示になる。倍率は従来どおり 1 のまま、前提注記で「1 枚分のみ加算」と補足する。

設計の詳細は [docs/superpowers/specs/2026-06-30-card-compare-broach-condition-notes-design.md](../superpowers/specs/2026-06-30-card-compare-broach-condition-notes-design.md) を参照。
