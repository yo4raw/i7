# 0088: 楽曲画像の取り込みを cron が失敗するあいだはローカルスクリプトで手動実行する

- 日付: 2026-09-19
- ステータス: 承認

## 背景

ADR 0076 で楽曲ジャケット画像の cron (`fetch-new-songs.yml`) を 6 時間おきに減らしたが、Miraheze は GitHub Actions の IP 帯を引き続き 403 で弾いており、2026-09-04 以降のすべての run が失敗している。同じ Cargo API はローカル端末からは取得できる。

その結果、TRIGGER記念日2026 の新曲 (ID 150, 151) の画像が本番に無く、イベント詳細の対象楽曲セクションが代替表示になっていた。

## 決定

cron はそのまま残し（ブロックが解ければ自動復旧する）、ワークフローの取り込みステップと同じ処理を **`npm run fetch-songs`** (`scripts/fetch-song-images-local.sh`) でローカル実行できるようにする。

- クローラー本体 `scripts/fetch-song-images.mjs` はワークフローと共有する。スクリプトは「不足画像の取得 → 新規ファイルの ID 列挙 → cron と同じ件名 (`🍱 楽曲ジャケット画像を追加: …`) でコミット」までを再現する
- push・PR・リリースは通常の手順（`develop` への PR → `main` へ fast-forward）で行い、スクリプトでは自動化しない
- 新曲が追加されてイベント対象楽曲 (`src/data/event-songs.json`) を登録するときに、あわせて実行する運用とする

## 検討した代替案

- **Miraheze のボットアカウント + BotPassword で認証して取得する** — ADR 0076 で見送り済み。認証で IP ブロックを回避できるか未検証で、資格情報の管理も増える
- **cron を止めて手動運用に一本化する** — ADR 0076 で見送り済み。ブロック解除時の自動復旧を捨てることになる
- **スクリプト化せず都度 `node scripts/fetch-song-images.mjs` を手で実行する** — 新規 ID の列挙とコミット件名を毎回手で揃えることになり、cron の履歴と件名がぶれる
