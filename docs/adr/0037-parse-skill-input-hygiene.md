# 0037: 判定ガード・判定拡大スコアダウンのスコア計算除外と発動率クランプ

- 日付: 2026-07-02
- ステータス: 承認

## 背景

1. `parseSkill`（teamBuilder.ts）の除外リストは `MISS→Good` と `判定強化(BAD→Perfect)` のみで、`判定ガード(MISS→Perfect)` と `判定拡大スコアダウン` が漏れていた。usable なスキルデータを持つ判定ガード 31 枚（うち UR 5 枚）とスコアダウン全 32 枚が `scoreUp` 扱いになり、value（実際はガード持続秒数などスコア点ではない値）を発動ごとに加点していた。スコア**ダウン**を正の加点として扱うのは符号レベルで誤りであり、`parseSkill` 自身のコメント（「判定補助系スキルはスコアに影響しないため null」）とも矛盾していた。
2. スキル発動率 `per` に 100 超の実データが存在する（ID 54/936 の L2〜L4 per=102〜106、ID 3144/3171 の L1 per=360 — おそらく 36.0% の入力ミス）。エンジンに検証がなく、期待値は `per/100` をそのまま乗算（per=360 なら理論最大の 3.6 倍）、MC と理論値は 100% 扱いと、3 つの推定量の解釈が食い違っていた。

## 決定

1. **`SKILL_TYPE` に `SCORE_DOWN`（判定拡大スコアダウン）を追加し、`parseSkill` の除外リストへ `MISS_TO_PERFECT` / `SCORE_DOWN` を加える。** 両スキルはスキルなし（null）扱いとし、判定補助系を無視する既存ポリシーへ揃える。減点・判定精度のモデル化は行わない（Perfect 前提のシミュレーションでは判定系スキルに意味がないため）。
2. **`parseSkill` で `per` を上限 100 にクランプする。** per>100 は「100% 発動」として期待値・MC・理論値の三者で解釈を一致させる。シート側のデータ修正（per=360 など）は別途行うが、エンジンとしても防御を持つ。

## 検討した代替案

- **スコアダウンを負のスコアアップとしてモデル化** — 実ゲームの減点仕様（判定拡大中のスコア半減）はノーツ判定に依存し、Perfect 前提のエンジンでは表現できない。無視（null）が一貫する。
- **per>100 をエラーにして該当カードを弾く** — カード自体は有効で、ユーザー操作で回避できないため過剰。クランプが最小影響。
- **シートデータの修正のみで対処** — 将来の入力ミス再発時に同じ非整合が再現するため、エンジン側の防御と両輪とする。

設計の詳細は [docs/superpowers/specs/2026-07-02-score-engine-audit-fixes-design.md](../superpowers/specs/2026-07-02-score-engine-audit-fixes-design.md) を参照。
