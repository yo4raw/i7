# 0084: イベント対象楽曲の SNS 共有ページを追加する

- 日付: 2026-09-08
- ステータス: 承認

## 背景

イベント配下の SNS 共有ページは特効衣装のまとめ (`/events/{id}/share/ur/` · `/share/ssr/`) だけで、対象楽曲を共有する手段がなかった。

対象楽曲は ADR 0081 でイベント単位 (`event-songs.json` の `byEvent`) に持てるようになり、イベント詳細にジャケット付きのセクションが出ている。ただしそこにあるのは曲名・難易度・秒数・ノーツ数だけで、どの曲を走るか決めるのに要る属性比率や、どの共通ブローチが効くかは楽曲詳細を 1 曲ずつ開かないと分からない。イベント期間中に SNS へ貼る用途では、曲ごとの判断材料が 1 枚に載っていてほしい。

## 決定

`/events/{id}/share/songs/` を追加し、**1 曲 = 1 枚の PNG** として一括ダウンロードできるようにする。

- パネルの内容はジャケット・曲名・アーティスト・難易度・秒数・ノーツ数、属性比率のドーナツと %、共通ブローチのスコア寄与 TOP10。いずれも楽曲詳細と同じ `attrDonutSvg()` / `buildBroachRanking()` を使い、計算をこのページ用に作らない
- **対象楽曲のうち最も秒数が短い曲にだけ「最短曲」バッジ**をジャケット左上に出す。周回効率で曲を選ぶときに真っ先に見る情報のため。同秒の曲が複数あればすべてに付ける
- パネル幅は特効衣装の共有ページと揃えて 880px 固定。ヘッダー帯（イベント名 / 種別 / 期間 / サイト名）も同じ体裁にし、複数の共有画像を並べて貼っても揃って見えるようにする
- 一括ダウンロードは ADR 0083 の `EventShareImage` の `panels` 経路をそのまま使う。ファイル名は `{ID}_{イベント名}_対象楽曲_1.png` …
- 生成対象は `byEvent` に曲が登録されたイベントだけ。未登録のイベントはページ自体を作らない
- 既存の共有ページと同じく `noindex` + sitemap 除外（`/events/\d+/share/` の既存パターンに含まれる）

## 検討した代替案

- **全曲を 1 枚の画像にまとめる** — 曲数ぶんの属性比率とブローチランキングが縦に積まれ、SNS の縮小表示で読めない。ADR 0083 で特効衣装について出したのと同じ結論
- **ノーツ内訳テーブル（ステージ別・属性別）も載せる** — 情報量は増えるが画像が縦に倍近く伸びる。属性比率とノーツ総数があれば曲選びの判断はつくため載せない
- **イベント詳細の対象楽曲セクションを画像化する** — セクションは一覧向けのレイアウトで、1 曲あたりの情報が共有には足りない。共有用のパネルを別に持つほうが両方の体裁を素直に保てる
