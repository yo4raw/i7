# 0036: 期待値スコアの縮小 rate 加重化と発動回数分母の実挙動統一

- 日付: 2026-07-02
- ステータス: 承認

## 背景

スコア計算エンジンの監査で、不変条件「期待値 ≤ 理論最大値」が破れるケースが確認された。

1. **縮小 rate 混在**: `calcExpectedScore` はデッキ内縮小スキルの **rate 最大値** を合算期待カバー秒全体へ適用する（shrink-skill-spec §5-4 の effectiveRate）。rate 1.6×1 枚 + 1.2×4 枚の編成で期待値が理論最大値を 31% 超過する再現例がある。spec §7-10 は「UI は Lv 一括選択なので rate 混在は起きない」としていたが、縮小カード 135 枚中 104 枚は Lv5 データが欠落しており `resolveEffectiveSkillLevel` が L4（rate 1.5）へ自動フォールバックするため、デフォルト設定でも rate 1.6/1.5 の混在は常態である。
2. **飽和キャップ**: 期待カバー率の 100% キャップは「非除外ノーツ全部カバー」を前提とするが、理論最大値の発動モデルでもノート型縮小は先頭 count−1 ノーツを構造的にカバーできず、キャップ飽和時に期待値が理論最大値を上回る。
3. **発動回数の二重定義**: `calcCardSkillMaxActivations`（表示用、先頭除外を引かない）と `calcShrinkActivationCount`（計算用、引く）が併存し、スキル発動タブ・スキル分布の二項分布 n が同じ行の期待値・最高値と異なる分母で表示されていた。

## 決定

1. **期待縮小スコアをスキルごとの rate 加重で計算する。** `shrinkExpected = floor(eligibleBaseScore × Σ[期待カバー秒ᵢ × (rateᵢ−1)] / effectiveSeconds)`（合算秒がキャップ超過時は比例縮小）。単一 rate の編成では従来式と数値完全一致し、既存の golden 値・スプレッドシートオラクル照合へ影響しない。
2. **期待カバー秒の上限を「構造的到達可能秒数」へ補正する。** ノート型縮小の初回発動前区間（デッキ内最小 count ノーツ分）をキャップから控除する。
3. **発動回数の分母を実挙動へ統一する。** `calcCardSkillMaxActivations` はノート型縮小について先頭除外ノーツを分母から引く（実シミュレーションのカウンタ挙動と同一定義）。
4. **残差はスキル全発動時の同段階合計でクランプして厳密保証する。** rate 加重・構造キャップ後も、縮小の秒→ノート離散化やキュー配信順の近似誤差で期待値が理論最大値を 1% 未満上回る縮退ケースが残る（飽和×rate 混在で実測 +0.4%）。このため縮小スキルを含むデッキでは、期待値のライブ終了スコアを `calcMaxScore` のバッジ適用前合計で min クランプする。クランプ時は shrinkExpected を差分調整して内訳の合計整合を保つ。`applyFinalBonus` は単調のため最終値も理論最大以下が保証される。追加コストは縮小スキルを含むデッキの期待値計算 1 回につき理論値相当の 1 パスで、縮小なしのデッキでは発生しない。

## 検討した代替案

- **クランプのみで対処（rate 加重を導入しない）** — 不変条件は保証されるが、rate 混在時の期待値が理論最大値に貼り付き MC の実測平均から大きく乖離する。根本原因の式修正（加重）と保証層（クランプ）の両方を採る。
- **丸め残差を許容しクランプを省く** — 編成組合計算の期待値モードでのコスト増を避けられるが、「期待値 ≤ 理論値」という UI 上の前提が縮退ケースで破れたままになる。実装後の計測で追加コストが縮小デッキ 1 評価あたり 1 パスに収まったため保証を優先。
- **rate 最大値のまま、カバー秒を rate 最大のスキル分に限定** — 複数縮小の寄与を過小評価し、MC の実測平均から大きく乖離するため却下。
- **Lv フォールバックを禁止して rate 混在を防ぐ** — Lv5 データ欠落カード（104 枚）がスキルなし扱いになり実態と乖離するため却下。
