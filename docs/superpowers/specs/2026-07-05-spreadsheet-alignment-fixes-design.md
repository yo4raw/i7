- 日付: 2026-07-05
- ステータス: 承認済み(ブレインストーミングセッションで全 14 件をユーザーが個別決定)

## 背景と目的

PR #376 の検証プロジェクトで、ota-life スプレッドシート v1.0.7 を正とした比較により実装バグ候補 B1〜B14 が確定した。本設計は、その 14 件について 1 件ずつユーザーが下した採否決定を記録し、修正の実装方針を定める。

## 決定(ユーザー確定・2026-07-05)

### シート準拠に修正する(11 件)

| # | 修正内容 | 主な対象コード |
|---|---------|--------------|

| B5 | スコアアップ活動回数の floor 先取りを廃止: 活動回数を小数のまま per×value と乗算し、カード別に floor → 合算(シート H38 準拠) | `simulation.ts` |

### 現状維持 → 意図的差異として ADR 0040 例外に追記する(3 件)

| # | 維持する現行挙動 | 理由 |
|---|----------------|------|
| B3 | センター/フレンドボーナス率はレアリティ別(UR=10%/SSR=7%/他=6%)を維持 | シートの一律 10% は UR 専用ツールとしての簡略化の可能性。実機のレアリティ別挙動を優先 |
| B11 | 共有ブローチのメイン/サブ区分・排他ルールは実装しない | データモデル+UI への波及が大きく、現状の利用実態で顕在化が限定的 |
| B14 | デッキ初期値は特訓済み・スキル Lv5 を維持 | 完凸前提で理論値を見る本サイトの UX として意図的な選択 |

### 保留

なし(全 14 件を決定済み)。

## 実装方針

- **ブランチ**: PR #376 をマージ後、main から `fix/spreadsheet-alignment-b1-b13` を作成(実施済み)
- **コミット粒度**: 1 defect = 1 コミット。各コミットで該当テストを green にしてから次へ
- **検証の軸**: `tests/unit/score/spreadsheetDiff.test.ts` の oracle↔engine 差分が修正のたびに縮むことを確認する
  - 目標: B5 修正後に scoreUp が両ゴールデン bit-exact となることを確認し、`KNOWN_DIFFS` から `scoreUp` を削除
  - shrink は ADR 0036 の rate 加重平均(W3、維持)が残るため known-diff のまま。reason を「B6/B7/B8 修正済み、残差は ADR 0036 由来のみ」に更新
- **既存テストの期待値更新**: engine 系単体テストの数値アサーションが多数変わる。各コミットで「新しい値が正しいことをオラクル/シート数式で説明できる」ことを更新の条件とする
- **ドキュメント整合(修正完了後)**:
  - `docs/spreadsheet-score-calc-diff.md` の B1〜B14 行を更新(修正済 → ✅ 一致(修正日付き)、維持 → 🔵 + ADR 0040 参照)
  - ADR 0040 に B3/B11/B14 の例外を追記
  - 新 ADR 0041「スプレッドシート準拠修正の実施(B1〜B13)」を追加
- **リリース**: 計算結果が実際に変わる(B6 は +20% 級)ため、PR マージ後にリリース(タグ push)+ release-tweet まで実施する

## 特に注意する波及範囲

1. **B1 のデータ配管**: サイトのカードマスター GViz(GID 480354522)に `sp_time`/`sp_value` 列が存在するか最初に確認する。存在しない場合はスプレッドシート側にデータがある前提を再確認し、列が本当に無ければ B1 は BLOCKED として報告(勝手に代替データ源を発明しない)
2. **B8 の波及**: `calcMaxScore` の置換は編成組合計算(`maxScoreFinder.ts`)・衣装比較の理論値表示・ADR 0036 の「期待値 ≤ 理論値」クランプへ波及する。按分式移行後もクランプ不変式(`expected ≤ max`)が保たれることをプロパティテスト(`expectedInvariants.test.ts`)で確認する
3. **B9+B10 の統合**: 上限ゲートは「limit 付き固有ブローチ全種類 × 同一カード ID 単位」に一本化される。`broachResolverBranches.test.ts` 等の既存テストが broach_type プール前提で固定化されているため、テスト自体の意図を書き換える(単なる期待値差し替えではなく仕様変更として)
4. **B2 のキャラ単位化**: ラビットノートは `i7_rabbit_notes`(キャラ名キー)で保存されているため、データモデルは変更不要。集計ロジックのみの修正

## テスト方針

- 各修正はまずオラクル/シート数式から期待値を導いた failing test(または golden 差分の縮小確認)を先に用意する(TDD)
- 最終状態で: `spreadsheetDiff.test.ts` unexpected ゼロ / `npm run test:unit` 全 green / Playwright E2E(スコア計算・編成組合計算)通過
- ゴールデンフィクスチャ(v1.0.6/v1.0.7)は変更しない — シート実測値であり修正の影響を受けない。変わるのは engine 側の出力と分類のみ

## 検討した代替案

- 全件一括シート準拠(B3/B11/B14 も修正): 実機挙動・UX 意図に反する箇所まで機械的に合わせることになり不採用(ユーザー個別判断で棄却)
- ドメイン別に複数 PR 分割: 計算結果の変わるリリースを複数回に分けるとユーザー告知が煩雑になるため、単一 PR・単一リリースを採用
