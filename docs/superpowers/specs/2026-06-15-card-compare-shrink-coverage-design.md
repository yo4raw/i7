# 衣装比較ページ 判定縮小タブの比較軸再設計（カバー秒数 / カバー率）

- 日付: 2026-06-15
- ステータス: ユーザー承認済み
- 関連 ADR: [0007](../../adr/0007-card-compare-page.md)（更新）＋新規 ADR

## 背景と問題

衣装比較ページ（`/card-compare/`）の判定縮小タブは現在、次の辞書式ソートで全衣装を並べている（`src/lib/score/cardStrength.ts` の `compareShrink`）:

1. 効果秒数（`skill.value` = 1発動あたりの縮小秒数）
2. 最大発動回数（`maxActivations = floor(発動機会 ÷ count)`）
3. 発動確率（`skill.per`）
4. 属性値合計

チャート（`ShrinkChart.svelte`）も「棒の高さ＝効果秒数」「秒数・回数・確率が一致する衣装は1列に縦積み」で表示している。

しかしこの前提は実態とズレている。判定縮小の実価値は **1発動あたりの秒数単独ではなく、曲全体でどれだけの時間を縮小で覆えるか**で決まる。コンボ／パーフェクトタイプの効果秒数は主にスコア期待値の上昇に寄与する要素であり、縮小衣装同士の比較で本質的に効くのは「曲全体のカバー量」である。

## 決定事項

辞書式（効果秒数を最優先）を廃止し、次の2つのカバー秒数を比較軸として一本化する。

### 比較軸

| 軸 | 式 | 意味 |
|----|----|----|
| **A. 最大カバー秒数** | `maxActivations × value` | 100%発動前提の上限縮小秒数 |
| **B. 期待カバー秒数** | `maxActivations × value × (per/100)` | 発動確率込みの期待縮小秒数 |

- `maxActivations = floor(発動機会 ÷ count)`
  - タイマータイプ: 発動機会 = 選択曲の秒数（`song.duration`）。よって A = `(曲秒数 ÷ count) × value`
  - コンボ／パーフェクトタイプ: 発動機会 = ノーツ数（`song.notes_count`）
- `value` = 1発動あたりの縮小秒数、`per` = 発動確率(%)
- 常に `B ≤ A`

### カバー率（併記）

カバー率 = カバー秒数 ÷ 選択曲の秒数（`song.duration`）。

| 指標 | 式 |
|------|----|
| 最大カバー率（A率） | A ÷ 曲秒数 |
| 期待カバー率（B率） | B ÷ 曲秒数 |

比較ページは1曲を全衣装に固定して並べるため曲秒数は全衣装共通の定数であり、**カバー率の並び順は対応するカバー秒数（A/B）の並び順と完全に一致する**。したがってカバー率は独立したソート軸にはせず、チャートの縦軸スケールとラベル併記に用いる。

### ソート

- ソートセレクタで **A（最大カバー秒数）／ B（期待カバー秒数）** の2択を提供する
- **デフォルトは B（期待カバー秒数）** — 発動確率込みの実期待縮小量が比較の主目的に最も近いため
- 並び順は選択中のキーの降順
- 従来の「同率縦積み」は廃止し、1枚ずつ並べる

## UI

### チャート（`ShrinkChart.svelte`）

- **縦軸 = カバー率(%)**。0〜100% を基準スケールとする（曲を変えても見た目のスケールが安定する）
- 各棒は **2段積み**:
  - 下の実体部 = **B率（期待カバー率）**
  - 上の薄い部分 = **A率 − B率**（発動確率による目減り分を可視化）
  - 棒の総高さ = A率（最大カバー率）
- A率が 100% を超える強力な縮小衣装は、軸上で 100% に振り切れ表示（クランプ）し、超過していることが分かる表現（上端マーカー等）を添える
- 並び順 = 選択中ソートキー（A or B）の降順
- 各棒のラベルに秒数とカバー率を併記する。例: `最大 18.0s (75%) / 期待 12.6s (53%)`
- サムネ下のスペック表示（発動条件・確率・属性値）は維持する

### 共通コントロール

- 縮小タブ表示中に **ソートセレクタ（A / B）** を追加する

### 詳細比較パネル

- 既存項目に加えて A・B のカバー秒数とカバー率を内訳表示に追加する（最良値を強調）

## 実装範囲

- `src/lib/score/cardStrength.ts`
  - `CardStrengthEntry` に `maxCoverSec`(A) / `expectedCoverSec`(B) を追加（`buildCardStrengthEntry` で算出）
  - `compareShrink`（固定辞書式）を、A/B いずれかのキーで降順比較するソート関数（または比較関数ジェネレータ）に置換
  - `shrinkTieKey`（同率縦積み判定）を削除
- `src/components/compare/ShrinkChart.svelte`
  - 縦軸をカバー率(%)に変更、2段積み（B率実体 + A率−B率の上乗せ）、100%クランプ表示
  - ラベルを秒数＋カバー率併記に変更
  - 同率縦積みロジックを削除
  - ソートキー（A/B）を props で受ける
- `src/components/CardCompare.svelte`
  - 縮小タブのソート state を追加（既定 B）、ソートセレクタ UI、`shrinkEntries` へのソート適用
  - 詳細比較パネルに A・B のカバー秒数／率を追加
- テスト
  - `cardStrength` のカバー秒数算出とソートの単体テスト（タイマー／コンボ両タイプ、A・B 両キー）
  - 既存 E2E（`tests/card-compare.test.ts`）の縮小タブ関連アサーションを新表示に合わせて更新
- ドキュメント
  - ADR 0007 を更新（縮小比較軸の変更を反映）し、新規 ADR を追加
  - `cardStrength.ts` 冒頭コメントの前提記述を更新

## 影響範囲外（変更しない）

- スコアアップタブ
- スコア計算エンジン（`simulation.ts`）— 既に「発動回数 × 持続秒」概念を持つが、今回の修正は比較ページのみ
- 比較ページの他の前提（UR 限定 / Perfect 前提 / センター無視 / 固有ブローチ込み / 特効トグル）
