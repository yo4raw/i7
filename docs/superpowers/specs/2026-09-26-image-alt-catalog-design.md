# public 配下の全画像に対する alt テキストカタログを生成する

- 日付: 2026-09-26
- 関連 ADR: 0094

## 目的

`public/assets/` 配下の 6,420 枚に対して、スクリーンリーダーに「誰の画像か」と「絵に何が描かれているか」が伝わる alt を持たせる。

現状 `src/` 内の `<img>` 21 箇所は `alt={card.cardname}` / `alt={song.song_name}` を機械的に埋めており、スクリーンリーダーには「Photo Collection -潤-」という文字列だけが届く。カードは絵が主役のメディアなので、この 1 つの alt では「誰のカードか」も「絵に何があるか」も伝わりきらない。

今回は sub-agent に実際の画像を見させ、絵の中身を日本語で描写させたうえで、シートが持つ正式名と合成した alt カタログを作る。**アプリへの結線は別タスク**とし、今回はカタログの生成と合成ロジックの実装までを行わない。

## 決定済みの前提

| 項目 | 決定 |
| ---- | ---- |
| alt の書式 | 識別情報 + ビジュアル描写（例: `御堂虎於の「午前0時の新月」カードイラスト（SSR・Beat）。ネオン街を背景に…`） |
| 言語 | 日本語（既存サイトの表示に合わせる） |
| 記述の分担 | sub-agent が画像を見て `visual` を書く。識別情報はシート値が優先 |
| 対象粒度 | 6,420 枚ではなく **3,527 件**（後述の重複除去） |
| 生成手段 | sub-agent 36 本をウェーブ 8 並行で |
| 結果の受け渡し | 必ずファイル（JSONL → JSON）。戻り文字列では受け取らない |
| アプリへの結線 | **今回やらない**。`src/` の `<img>` 21 箇所は `cardname` のまま据え置き |
| 既存データの改変 | なし。`tests/fixtures/`・シート・`public/` の元画像には触れない |
| 装飾扱いの画像 | 今回の対象外（`DistributionChart.svelte` / `DeckSkillDistribution.svelte` の `alt=""`） |

## 1. 対象母数（確定値）

| 種別 | 画像ファイル | シートで識別可 | 孤児（シートに行が無い） |
| ---- | ------------ | -------------- | ------------------------ |
| カード | 3,376 | 2,871 | 505 |
| 楽曲 | 151 | 151 | 0 |
| 合計 | 3,527 | 3,022 | 505 |

内訳の根拠（2026-09-26 に実測）:

- `public/assets/cards/` = 2,893 枚（全て 800x1200）。**2,871 枚がシート（gid 480354522）の 2,872 行に `ID` で一致**。残り 22 枚は行が無い
- `public/assets/th_cards/` = 3,376 枚（全て 200x300）。2,893 枚は上記カードと表裏。**483 枚だけサムネしかない**（フル画像なし）
- シートの `ID` に対応する画像が 1 枚だけ欠けている（`th_cards/` に存在しない `ID` がある）。画像の欠落ではなくシート行のみで|alt カタログの対象外
- `public/assets/songs/` = 151 枚（全て 300x300）。**151 枚すべてがシート（gid 1083871743）の 263 行のいずれかに一致**（`曲名` / `アーティスト名` を持つ）

### 重複除去のルール

`cards/<id>.webp` と `th_cards/<id>.webp` は同一作品の表裏なので、alt は共有する。生成対象は

- カード: **3,376 件**（ID ごとに 1 件だけ。フル画像があれば thereof、無ければ 200x300 のサムネを使う）
- 楽曲: **151 件**

= 3,527 件。うち 800x1200 を読むのは 2,893 件だけで、残り 634 件（483 枚のサムネ + 151 枚のジャケット）は 300x300 以下。

## 2. 成果物

### `src/data/image-visual.json`（生成物・commit 対象）

sub-agent の出力を確定論スクリプトで整形したカタログ。alt 完成形ではなく**絵の中身の描写のみ**を保持する。

```json
{
  "cards": {
    "1000": { "v": "紫髪の青年が黒い中国風ジャケット姿で胸を張って立ち、右手に赤い中国結を掲げたまま左手を手前に差し出している" },
    "1958": { "v": "橙色の短髪の青年が薄紫のシャツに紺の太いマフラーを巻いて両肩から垂らし、左手を頭上へ掲げて笑いながら視線をこちらへ送っている", "n": "RIKU NANASE" }
  },
  "songs": {
    "100": { "v": "7人が幾何学模様と星形の背景に重なり、各人の名前が latin 文字で添えられ、下部に金色の曲名が入っている" }
  }
}
```

- `v`（必須）… 絵の中身の描写。40〜70 文字の日本語
- `n`（任意）… **シートに対応行が無いカードにのみ付く**。画像に印字されていたキャラクター名を印字どおり控えたもの

`src/data/event-songs.json` と同じ `src/data/` 配下の生成データとして扱う。

### `src/lib/imageAlt.ts`（commit 対象）

alt を合成する純関数。シート値と `image-visual.json` を合成する。**今回はアプリ側から呼び出されない**（結線は別タスク）。

| 関数 | 戻り値 |
| ---- | ------ |
| `cardAlt(card: Card, entry: VisualEntry \| undefined): string` | `{name}の「{cardname}」カードイラスト（{rarity}・{attribute}）。{v}` |
| `songAlt(song: Song, entry: VisualEntry \| undefined): string` | `{アーティスト名}の楽曲「{曲名}」ジャケット。{v}` |
| `orphanCardAlt(entry: VisualEntry): string` | `{n}のカードイラスト。{v}`（`n` が無ければ `{v}` のみ） |

- 項目の欠けは**空文字として除去**する（`card.cardname` が null のとき括弧が壊れないように）
- `v` が取れない（`entry` が `undefined` / `v` が空）ときは、識別情報だけの文字列へフォールバックする
- 結線時に `image-visual.json` がクライアントバンドルへ入らないよう、import は **build 時のみ通る経路**（`src/lib/data/fetch*.ts` など）に限定する

`src/lib/**` は Vitest のカバレッジしきい値 95%（statements / branches / functions / lines）の対象なので、`tests/unit/imageAlt.test.ts` を必ず残す。

## 3. 生成パイプライン

作業領域はすべて `tmp/`（gitignore 済み）。

### 3.1 `scripts/image-alt/build-manifest.mjs`

- カード（gid 480354522）と楽曲（gid 1083871743）を GViz 経由で取得する。取得処理は `src/lib/data/gviz.ts` と同じ流儀で書き、`scripts/lib/util.mjs` の `fetchRetry` を使う
- `public/assets/{cards,th_cards,songs}` を走査し、3,527 件の Manifest を作る

Manifest 1 件の形:

```json
{
  "kind": "card",
  "id": "1000",
  "readPath": "tmp/image-alt/scaled/cards/1000.webp",
  "fallbackPath": "public/assets/th_cards/1000.webp",
  "hasDbRow": true
}
```

`hasDbRow: false` のときだけ sub-agent にも印字名の控える求める。`readPath` が存在しない場合は `fallbackPath` を読む。

### 3.2 `scripts/image-alt/scale-cards.mjs`

- `public/assets/cards/` の 2,893 枚を sharp で 512x768 の lossy webp に変換し `tmp/image-alt/scaled/cards/` へ出す
- 800x1200 は約 1,280 画像トークン、512x768 は約 524。約 59% 削減
- 出力サイズは約 145MB（`tmp/` なので問題なし）
- サムネ（200x300）と楽曲（300x300）は変換せずそのまま使う
- **`public/` を書き換えない**（元画像を壊さないことが最優先）

### 3.3 パイロット（4 枚）

本番 36 本を叩く前に、4 枚だけで sub-agent を走らせ、描写の書式をユーザーが確認する。**パイロットで承認された書式以外を本番に使わない**。パイロットの出力は `tmp/image-alt/pilot.jsonl` に残し、書式の比較用として保持する（本番バッチとは混ぜない）。

### 3.4 本番（sub-agent 36 本）

- 1 バッチ = 100 枚。カード 3,376 → **34 バッチ**（100 × 33 + 76）、楽曲 151 → **2 バッチ**（76 + 75）
- ウェーブ 8 並行、5 ウェーブ
- 各 sub-agent に渡すのは、担当 Manifest のスライス（`{kind, id, readPath, needPrintedName}`）と描写ルールのみ
- 各 sub-agent の書き出し先は `tmp/image-alt/batch-<NN>.jsonl`（1 行 1 レコード）
- 戻り値は「書き終えた」の一言だけ。3,527 レコードを戻り文字列として受け取らない

### 3.5 `scripts/image-alt/merge-visual.mjs`

- `tmp/image-alt/batch-*.jsonl` を全部読み、`src/data/image-visual.json` を整形済み（2 スペース・改行あり）で書き出す
- 入口でバッチ単位の「ファイル存在 + 件数」を検出し、書けていないバッチを列挙して exit≠0 にする（再投の判断材料）
- 書き出す前に第 5 節の検証をすべて通す

## 4. sub-agent への指示（描写ルール）

**やること**

1. 渡されたスライスの `id` と `readPath` を 1 対 1 で受け取る
2. 各 `readPath` を `read` ツールで実際に開く
3. 開けた画像 1 枚につき、描写を 1 レコードにする
4. `tmp/image-alt/batch-<NN>.jsonl` に 1 行 1 JSON で書き出す
5. 全件を書き終えたら「書き終えた」とだけ報告する（レコード本文を報告に含めない）

**書き方のルール**

1. 1 画像につき 1 レコード。**必ず全件を書く**。飛ばさない
2. `v` は 40〜70 文字の日本語
3. 書き始めは主語（`〜が` / `〜の`）。助詞から始めない
4. 描写の順序は 人物 → 服装 → ポーズ・表情 → 背景
5. **キャラクター名・カード名・レアリティ・属性は `v` に書かない**。合成段で足すので、ここに混ぜると二重になる
6. ローマ字・英語は書かない（`n` を除く）
7. 主観語（`美しい` `かわいい` `かっこいい`）は書かない
8. 画像に印字されている文字（カード名、ロゴ、看板など）は `v` に拾わなくていい
9. 1 枚も読めなかった場合は `{"kind":"card","id":"<id>","v":"","note":"判読不能"}` を書き、**それ以上推測しない**
10. 性別・年齢帯が判断できない場合は断定しない

**出力形式**

Markdown もコードフェンスも添えず、1 行 1 JSON で書く。

```
{"kind":"card","id":"1000","v":"紫髪の青年が黒い中国風ジャケット姿で胸を張って立ち、右手に赤い中国結を掲げたまま左手を手前に差し出している"}
{"kind":"card","id":"1958","v":"橙色の短髪の青年が薄紫のシャツに紺の太いマフラーを巻いて両肩から垂らし、左手を頭上へ掲げて笑いながら視線をこちらへ送っている","n":"RIKU NANASE"}
```

## 5. 検証（受け入れ基準）

`scripts/image-alt/merge-visual.mjs` が以下をすべて確認する。1 つでも落ちたら exit≠0 とし、該当 ID を列挙する。

1. **網羅性** … `public/assets/{cards,th_cards,songs}` の ID 集合と `image-visual.json` のキー集合が一致する
2. **空 `v` の検出** … `v` が空のレコードが 1 件でもあるなら、その ID を列挙して落とす（再試行対象を特定できるように）
3. **長さ** … `v` が 10 文字未満または 200 文字超のものを列挙して落とす
4. **禁止語** … `v` に `TODO` / `placeholder` / `画像` / `不明` / `?` / `？` を含むものを列挙して落とす
5. **キャラクター名の混入** … `v` に `CHARACTERS` のいずれかが含まれるものを列挙して落とす（描写ルール 5 の違反検出）。ただし `百` / `千` は一般語彙と衝突するためこの検査から除外し、手動目視で確認する
6. **構造** … `cards` / `songs` のネストが正しく、`n` が任意であること

## 6. スコープ外

- `src/` の `<img>` 21 箇所の書き換え（**別タスク**。`alt={card.alt}` 化の段）
- 装飾目的の `alt=""`（`DistributionChart.svelte` / `DeckSkillDistribution.svelte`）
- `public/` 直下の PWA / favicon / apple-touch-icon（サイト表示に使われていない）
- OGP 画像

## 7. リスクと対処

| リスク | 対処 |
| ------ | ---- |
| sub-agent が 100 枚を処理しきれず欠落する | 検証 1・2 が欠落 ID を列挙する。欠落分だけの小さなバッチを作り直して再投する |
| 描写の粒度がばらつく | パイロットで書式を先に確定させる。書式 revise が必要になっても `imageAlt.ts` の模板を直すだけで済み、`v` の再取得は不要 |
| 一部 sub-agent がファイルを書かずに終わる | `merge` の入口でバッチ単位のファイル存在と件数を検査し、書けていないバッチだけを再投する |
| シート値と画像の中身が食い違う | カードはシート値のみを alt の識別情報に使うので|alt は常にシートに従う。食い違いは本次のスコープ外として別途データ整備に回す |
| token 数が読めない | 縮小により 3,527 件の画像トークンは約 1.6M、出力を含めて 2〜2.5M を見込む。`scale-cards.mjs` を回さず元画像（800x1200）を直接読む運用に切り替えれば約 4.5M |
