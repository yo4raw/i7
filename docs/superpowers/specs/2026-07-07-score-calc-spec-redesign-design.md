# スコア計算 仕様解説ページ全面リデザイン 設計書

日付: 2026-07-07
ステータス: 承認（ユーザー承認済み、§3 以降は委任により確定）
関連 ADR: 0043

## 目的

`/score-calc/spec/` を、判定縮小スキル特化の解説から**実装されているスコア計算パイプライン全体**を SVG 図解で説明するページへ全面リライトする。

## 決定事項（ユーザー確認済み）

1. **スコープ**: 計算ロジック全体（チーム属性値 → 素点 → スコアアップ → 縮小 → 最終補正 → 統計）をカバー
2. **構成**: 1 ページに全章を縦置き（目次ナビ付き）
3. **既存の縮小解説**: 図・playground 含め全面作り直し（ビジュアル言語を全章で統一するため）
4. **読者層**: 2 層構造 — 本文はプレイヤー向け平易記述、各章に `<details>` の「実装詳細」折り畳みで式・変数名・floor タイミングを収容
5. **動的要素**: 静的 SVG 中心 + 要所（縮小章）に playground
6. **アプローチ**: パイプライン縦断型の章立て + 全章共通のデモ実数値（A+B ハイブリッド）

## 章立て

| 章 | 内容 | 主な SVG |
|---|------|---------|
| 0. 全体像 | パイプライン俯瞰図。各章冒頭に現在地ハイライト版を再掲 | 横長フロー図 |
| 1. チーム属性値 | 基礎値 → 特訓 → 特効倍率 → ラビットノート → ブローチ → センタースキル | 積み上げ内訳図 |
| 2. 1ノーツの素点 | ノートレート（白 2.5% / 色 3.0%）× ライト倍率（1.0〜3.0）、アシスト ×1.2 | ライト倍率チャート + 計算ステップ図 |
| 3. スコアアップスキル | ノート型（コンボ/Perfect）・タイマー型、count/per/value | 発動タイムライン図 |
| 4. 判定縮小スキル | 発動判定・キューイング・先頭除外・カバー率・加算式 | タイムライン + playground |
| 5. 最終補正 | バッジ倍率・ブローチスコア直接加算（種類9） | 最終式分解図 |
| 6. 理論値・期待値・MC | min/max/期待値の関係、MC 分布、全発動モード 2 種 | ヒストグラム + 3 値位置図 |

各章末に「ここまでの積み上げスコア」バー（期待値経路の実数値）を表示する。

## ビジュアル言語（全 SVG 共通規約）

- 段階別配色: 属性値=indigo 系 / 素点=sky 系 / スコアアップ=amber 系 / 縮小=orange 系 / 最終補正=emerald 系 / 統計=グレー+赤アクセント
- ゲーム属性（Shout/Beat/Melody）を示す場合のみ `ATTR_HEX` を使い、凡例必須
- floor（切り捨て）発生箇所は ⌊ ⌋ マーカーで統一表示
- 俯瞰図は章冒頭で該当ブロックのみハイライトした「現在地」ミニ版を再掲
- `viewBox` + `class="w-full h-auto"`、横長図は `overflow-x-auto` コンテナ
- ライトテーマ固定（`dark:` バリアント禁止）。チャート系 CSS 変数（`--chart-*`）は継続利用
- ユーザー可視テキストは「衣装」（用語ポリシー）。内部変数名は `<details>` 内のみ

### specDemo.ts の注意点

- `tests/fixtures/index.ts` を `src/` から import する（ビルド時静的 import。クライアントバンドルには含めない — spec.astro はプリレンダリングのため frontmatter でのみ参照）
- fixtures 再生成（`npm run extract-fixtures`）でカードデータが変わっても、数値はビルド時に再計算されるため文章と数値の不整合は起きない（文中に数値を直書きしない）
- MC は seed 固定・1000 試行で決定論化

## エラーハンドリング / エッジケース

- デモデッキの ID が fixtures から消えた場合はビルドを fail させる（`findCardById` が throw）— 静かな劣化より検出を優先
- SVG は全て `role="img"` + `aria-label` を付与

## テスト方針

- 単体: specDiagrams の各生成関数が well-formed な SVG 文字列を返すこと、specDemo の数値がエンジン関数の直接呼び出しと一致すること
- E2E: 全章見出しの表示、SVG 描画数、playground 操作、導線リンク（dev サーバー再利用で実行）

## 検討した代替案

- **B案: 実例トレース型のみ** — 手書き数値のメンテコストが高く網羅性が低いため、数値をビルド時生成にして A 案に統合
- **C案: リファレンス辞書型** — 全体の繋がりが伝わらないため不採用
- **章ごとのサブページ分割** — ナビゲーション設計コストとページ数増のため不採用（1 ページ縦置き）
