# 衣装比較・詳細パネルにスコア分布を追加する設計

- 日付: 2026-06-18
- ステータス: ユーザー承認済み（モックアップ確認込み）
- 関連 ADR: [0024](../../adr/0024-card-compare-distribution.md)
- 既存設計: [2026-06-11 衣装比較ページ](2026-06-11-card-compare-design.md) / [2026-06-15 スコアアップ最大値重ね](2026-06-15-card-compare-scoreup-max-overlay-design.md)

## 背景と目的

衣装比較の詳細パネル（最大4枚）は現在、期待値（スキル期待値込み合計）と最大値（100%発動時の上限）を数値で並べている。しかし最大値は「全発動機会で発動成功」した場合の理論上限であり、発動回数が多い衣装ほど実際には到達確率が極小（事実上到達しない）になる。「期待」と「最大」の2点だけでは、

- どれだけ安定して稼げるか（ばらつきの小ささ）
- 上振れがどれだけ起こりやすいか（最大近辺の到達確率）

が見えず、衣装の比較判断がしにくい。

そこで詳細パネルに各衣装の**スコア分布**を重ねて描画し、ばらつきと「最大の◯%以上を出せる確率」を直感的に比較できるようにする。

## 決定事項

| 項目 | 決定 |
|------|------|
| 表示場所 | 詳細比較パネル内（ランキングチャートは現状維持） |
| 可視化 | 絶対スコア軸の重ね合わせ密度曲線（最大4枚を1チャートに重ねる） |
| しきい値の基準 | スキル上乗せ分（発動成功分）に対する % |
| しきい値線 | 衣装ごとに独立した縦線。各線を個別にドラッグして % を変更でき、`P(≥)` を個別表示 |
| 一括スライダー | 全線を同じ % に一括セットする単一スライダーを併設（初期位置合わせ・キーボード操作用）。その後の個別ドラッグで微調整可能 |
| 計算方式 | 二項分布の解析計算（厳密）。モンテカルロ不使用 |
| 状態の永続化 | しない（ページ方針に準拠・YAGNI） |

## 計算モデル（解析的・デッキ非依存）

スキル発動の成否は各発動機会で独立試行とみなせるため、発動成功回数 `K` は二項分布に従う。

```
K ~ Binomial(n, p)
  n = 最大発動回数 (CardStrengthEntry.maxActivations)
  p = 発動率 (skill.per / 100)
```

- **スコアアップ系**: 合計スコア `= baseScore + K × value`（`value` = スキル効果値）。スコア軸上の PMF を得る
- **判定縮小系**: カバー秒数 `= K × value`（`value` = 1発動あたり縮小秒数）。秒数軸上の PMF を得る
- 既存の `skillExpected = floor(n·p·value)` / `skillMax = n·value` / `expectedCoverSec = n·value·p` / `maxCoverSec = n·value` と整合する（いずれも同じ `n, p, value` から導出）

### しきい値以上を出す確率

しきい値はスキル上乗せ分に対する割合 `t`（0〜1）で表す。上乗せ分が `t` 以上になるのは `K × value ≥ t × n × value`、すなわち `K ≥ t·n` のとき。

```
k_min = ceil(t · n)
P(≥ t) = Σ_{k = k_min}^{n} PMF(k)   （二項分布の右裾）
```

`value` に依らず `t` と `n` だけで決まる。スコアアップ・縮小で同一の式。

### 退化ケース

- スキルなし／判定補正系（`skillMax = 0` かつ非縮小）: 分散ゼロ。スコアは `baseScore` の1点スパイク。しきい値線・ドラッグ対象外（「ばらつきなし」として表示）
- `p = 1`（発動率100%）: 全質量が `k = n`。最大値に1点集中
- `p = 0` / `n = 0`: 全質量が `k = 0`（土台のみ）

## モジュール構成

1枚あたりの分布計算は UI 非依存の純粋関数として切り出す。

| ファイル | 役割 |
|---------|------|
| `src/lib/score/cardDistribution.ts`（新規） | `CardStrengthEntry` から二項 PMF・しきい値裾確率を計算する純粋関数 |

想定 API（実装時に詳細確定）:

- `binomialPmf(n, p): number[]` — `k = 0..n` の確率配列（総和は 1）
- `cardScorePmf(entry): { metric: 'score' | 'cover'; points: { x: number; prob: number }[] }` — 各成功回数 `k` を絶対値（スコア or 秒数）にマップした分布点
- `reachProbability(entry, t): number` — 上乗せ分の `t` 以上を出す確率（右裾）
- `scoreToThreshold(entry, x): number` — 絶対値 `x`（ドラッグ位置）→ 上乗せ分割合 `t` への逆変換

## UI

### 配置

詳細比較パネル（`CompareDetailPanel.svelte`）の既存数値表に加え、分布チャート領域を新設する。数値表（属性値・期待・最大など）は絶対値の確認用に残す。

### チャート（重ね合わせ密度曲線）

- 横軸 = 実際の値（スコアアップ: 合計スコア／縮小: カバー秒数）。選択中の同種衣装の `[最小ベース 〜 最大]` を共有スケールにする
  - スコアアップのベース = `baseScore`、最大 = `maxTotalScore`
  - 縮小のベース = 0 秒、最大 = `max(maxCoverSec)`
- 各衣装を半透明の塗り + 実線で重ねる（最大4枚）。シリーズ4色（属性色とは別の固定パレット。同属性衝突を避けるため）＋サムネ凡例で色と衣装を対応付け
- 縦軸は各曲線を自身のピーク値で正規化（density の形＝ばらつきの比較が目的。曲線間の面積の絶対比較はしない。到達確率は数値で別途表示）
- SVG で描画。ライトテーマ固定、チャート配色変数（`--chart-grid` 等、`src/styles/global.css`）を踏襲

### しきい値線（衣装ごと独立・ドラッグ可能）

- 衣装ごとに色を合わせた縦の破線を引く。線上部にドラッグ用ハンドル
- 各線を独立してドラッグ可能。ドラッグ位置 `x` → `scoreToThreshold(entry, x)` で `t` に換算 → `k_min`・`P(≥)` を即時更新
- 各線に「上乗せ分の◯% / P=◯%」を表示（凡例または線の近傍）
- タッチ操作対応（パネルはスマホで横スクロール）

### 一括スライダー

- チャート上部に単一スライダー（0〜100%）を置く。動かすと全衣装の線を同じ `t`% にセットする
- キーボード操作・初期位置合わせの導線。セット後は各線を個別ドラッグで微調整できる
- 初期値は 80%（上振れ近辺の比較に有用な既定）

### スコアアップ・縮小の混在

詳細パネルの選択はタブをまたいで共有されるため、スコアアップ衣装と縮小衣装が同時に選択され得る。スコア（点）と秒数は単位が異なり1軸に重ねられないため、

- 同種衣装ごとに最大2つのチャート（スコア用・カバー秒数用）に分割して表示する
- 通常は1タブ内での選択なのでチャートは1つだけ表示される

## テスト

### 単体テスト（Vitest, `tests/unit/score/cardDistribution.test.ts`）

- `binomialPmf` の総和が 1（浮動小数誤差許容）
- `reachProbability` の右裾計算が直接和と一致（既知の小さな `n, p` で検証）
- 縮小衣装で `value` = 縮小秒数として秒数軸にマップされる
- 退化ケース（`skillMax = 0` / `p = 1` / `p = 0`）で期待どおりのスパイクになる
- `scoreToThreshold` が `reachProbability` の逆方向と整合する

### E2E テスト（Playwright, `tests/card-compare.test.ts` に追加）

- 詳細パネルを開くと分布チャートが描画される
- 一括スライダーを操作すると `P(≥)` 表示が変化する
- スコアアップ衣装・縮小衣装の混在選択でチャートが2つに分かれる

## 検討した代替案

- **正規化軸（しきい値線1本・共通）**: スライダーの「上乗せ分%」と素直に対応し4枚重ねてもスッキリするが、絶対スコアの高低が見えない。ユーザーは得点位置も同時に見たいため絶対スコア軸を採用
- **単一の絶対スコアしきい値線**: 線は1本で最も単純だが、しきい値が「上乗せ分%」でなく絶対スコアになり、衣装ごとの上振れ起こりやすさの比較が弱い。衣装ごと独立線を採用
- **確率バーのみ（分布の絵を出さない）**: 実装最小だがばらつきが見えず、本機能の目的（安定度の可視化）を満たさないため不採用
- **モンテカルロシミュレーションの流用**: 1枚あたりは単純な二項分布で解析的に厳密計算でき、MC は近似かつ低速なため不採用
