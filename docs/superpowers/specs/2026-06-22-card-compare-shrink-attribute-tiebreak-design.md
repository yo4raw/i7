# 衣装比較 判定縮小タブ: 属性値タイブレーク化とカバー率用語統一

- 日付: 2026-06-22
- ステータス: ユーザー承認済み
- 関連 ADR: [0007](../../adr/0007-card-compare-page.md) / [0016](../../adr/0016-card-compare-shrink-coverage.md) / 0027（本変更で追加）

## 背景と目的

衣装比較ページ（`/card-compare/`）の判定縮小タブは、ADR 0016 でカバー秒数（最大／期待）の一本軸ソートに変更された。その結果、属性値はカバー率が完全一致したときのタイブレークにしか効かなくなっている。さらに、現状はタイブレークに使う属性値の定義が表示と食い違っている:

- **表示**（チャート脚注・詳細パネルの「属性」）= `baseScore`（選択曲での属性値由来スコア）
- **ソートのタイブレーク** = `appealTotal`（Shout+Beat+Melody の曲非依存な単純合計）

多色拮抗曲では両者がズレるため、「属性値が考慮されていない／表示と並びが合わない」という体験になっていた。本変更で、縮小衣装の評価に属性値を一貫した定義で反映する。

あわせて、ソート項目のラベルが「カバー秒数」だが、チャート縦軸・詳細パネルは実際にはカバー率(%)で見せている。曲を全衣装で固定するためカバー秒数とカバー率は比例（並び順は同一）であり、ユーザー可視テキストを「カバー率」に統一して用語のねじれを解消する。

## 決定事項

### 1. 縮小タブのソートに属性値を反映（タイブレークの定義変更）

`src/lib/score/cardStrength.ts` の `compareShrinkBy` のタイブレークを変更する。

```
現状: カバー率(max|expected) 降順 → appealTotal 降順
変更: カバー率(max|expected) 降順 → baseScore 降順
```

- 辞書式は **2段（カバー率 → 属性値由来スコア）** のシンプル構成。発動確率は期待カバー率（expected）に畳み込み済みのため、中間キーには入れない。
- タイブレークの「属性値」は **`baseScore`（選択曲での属性値由来スコア）** に統一し、チャート脚注・詳細パネルの「属性」表示とソート優先順位の定義を一致させる。
- `CardStrengthEntry` に既存の `baseScore` を使うため、データ構造の追加・計算ロジックの新設は不要。変更は比較関数1行＋JSDoc。

### 2. 用語を「カバー率」に統一（ユーザー可視テキストのみ）

並び順そのもの（曲固定で秒数＝率の比例関係）と内部識別子は変えず、ユーザーに見えるラベル・表示値の単位のみ率に揃える。

| ファイル | 変更 |
|---------|------|
| `src/components/CardCompare.svelte` | ソートドロップダウン「最大カバー秒数 / 期待カバー秒数」→「最大カバー率 / 期待カバー率」 |
| `src/components/compare/CompareDetailPanel.svelte` | 行ラベルを「最大カバー率 / 期待カバー率」に変更。`coverLabel` の出力を `Ns (P%)` → `P% (Ns)`（率を主、秒数を括弧）に変更 |
| `src/components/compare/ShrinkChart.svelte` | 脚注の「並び順: 〜の降順」表記の軸名を率表現に |
| `src/pages/card-compare/index.astro` | ページ説明文（「最大／期待カバー秒数」）を率表現に |

### 3. 変更しないもの

- 内部識別子 `maxCoverSec` / `expectedCoverSec`（フィールド名・変数名）。CLAUDE.md の用語ポリシー（内部識別子は維持、ユーザー可視テキストのみ変更）に従う。
- `CardStrengthEntry` のデータ構造。
- ソート順そのもの。曲を全衣装で固定するためカバー秒数とカバー率は比例し、ラベルの単位を変えても並びは一致する。
- ソート軸の選択肢（最大／期待の2択、デフォルト期待）。ADR 0016 の方針を維持する。

## 影響範囲とデータフロー

- `compareShrinkBy` は `CardCompare.svelte` の縮小タブ並べ替えで使用される純粋関数。`baseScore` は `buildCardStrengthEntry` で選択曲ごとに算出済みのため、曲・特効・ブローチの変化にも追従する。
- `CompareDetailPanel` は既に `songDuration` を props で受け取り `coverLabel` 内で率を算出しているため、表示形式変更に追加の配線は不要。

## テスト

- 単体テスト `tests/unit/score/cardStrength.test.ts` に `compareShrinkBy` のタイブレークケースを追加:
  - カバー率（max / expected）が同値で `baseScore` が異なる2件 → `baseScore` 降順で並ぶこと
  - `appealTotal` が逆順でも `baseScore` 順が優先されること（定義変更の回帰防止）
- E2E `tests/card-compare.test.ts`: ソートドロップダウンの選択肢ラベルが「カバー率」表記であることの確認（既存テストにラベル依存があれば更新）。

## エラー処理

- 既存挙動を踏襲。`songDuration` が 0/不明な場合、`coverLabel` の率は `-` 表記（現行と同じ）。

## 検討した代替案

- **カバー率と属性値を独立した別ソート軸として選択**（ドロップダウンに「属性値由来スコア」を追加）— 縮小衣装はカバー率で並べるのが本筋であり、属性値は同率内の決定に効けば足りるため、軸の追加はせずタイブレーク強化に留めた。
- **縮小を期待上乗せスコアに換算して属性値と合算した単一スコアで並べる** — ADR 0007 / 0016 が「縮小の単一数値化はしない」と明確に否定済みの方向のため不採用。
- **発動確率を中間キーに入れる3段辞書式** — 期待カバー率に確率が畳み込まれており、最大カバー率ソート時に効く差分も限定的なため、シンプルな2段に留めた。
- **ソートラベルのみ率に変え、詳細パネルは秒数表記のまま** — サイト内で「カバー率」と「カバー秒数」の用語が割れるため、可視テキストは率に統一した。
