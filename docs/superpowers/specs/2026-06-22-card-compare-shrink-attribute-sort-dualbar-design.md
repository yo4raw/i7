# 衣装比較 判定縮小タブ: 属性値由来スコア順ソートの追加とデュアルバー表示

- 日付: 2026-06-22
- ステータス: ユーザー承認済み
- 関連 ADR: [0016](../../adr/0016-card-compare-shrink-coverage.md) / [0027](../../adr/0027-card-compare-shrink-attribute-tiebreak.md) / 0028（本変更で追加）

## 背景と目的

衣装比較ページ（`/card-compare/`）の判定縮小タブは、カバー率（最大／期待）を主キーに並べ、属性値由来スコアは同率時のタイブレークに使っていた（ADR 0027）。

しかし縮小衣装を選ぶ際、「その曲でどれだけ属性値スコアを稼げるか」で並べたい場面がある。縮小スキルの価値はカバー率で測れるが、衣装自身の属性値スコアも編成全体のスコア土台に効くため、属性値由来スコアの高い順に見たいという要望が出た。

そこで、並べ替えの選択肢に「属性値由来スコア順」を追加し（初期選択をこれにする）、あわせてチャートをデュアルバー化してカバー率と属性値スコアを横並びで同時に視覚化する。

## 決定事項

### 1. ソートに「属性値由来スコア順」を追加（`cardStrength.ts`）

`ShrinkSortKey` を `'max' | 'expected'` から **`'max' | 'expected' | 'attr'`** に拡張し、`compareShrinkBy` を次の通りにする。

| キー | 第1キー（降順） | タイブレーク（降順） |
|------|----------------|----------------------|
| `'attr'`（**デフォルト**） | `baseScore`（その曲での属性値由来スコア） | 期待カバー率（`expectedCoverSec`） |
| `'expected'` | 期待カバー率（`expectedCoverSec`） | `baseScore` |
| `'max'` | 最大カバー率（`maxCoverSec`） | `baseScore` |

- `'expected'` / `'max'` の挙動は ADR 0027 のまま（カバー率主キー → `baseScore` タイブレーク）。
- カバー率は曲固定のため秒数と率が比例し、並び順は一致する。

### 2. ドロップダウン（`CardCompare.svelte`）

縮小ソートの `<select>` に「属性値由来スコア」の選択肢を追加し、初期値を `'attr'` にする。

```
属性値由来スコア（デフォルト） / 期待カバー率 / 最大カバー率
```

表示範囲（所持のみ／全件トグル）・表示件数の仕組みは変更しない。状態の永続化もしない（ADR 0007 を踏襲し、毎回初期状態 `'attr'`）。

### 3. チャートをデュアルバー化（`ShrinkChart.svelte`）

各衣装の列に縦棒を **2本横並び** にする。

- **左＝カバー率バー**: 現状の2段積み（濃い＝期待カバー率／薄い＝最大との差、発動率による目減り）。曲尺基準で 0〜100%、100% 超は ▲ で振り切れ表示。
- **右＝属性値バー**: その曲での属性値由来スコア（`baseScore`）を、**表示中エントリの最大 `baseScore` を 100% とした相対高さ**で描く。カバー率とは単位が異なり絶対軸を共有できないため相対正規化する。色はカバー率と区別できる別色（`--chart-*` 系のトークン or 既存パレットから選定）。
- 並び順はドロップダウンの選択キーに従う。`'attr'` 選択時は右の属性値バーが単調減少、左のカバー率バーは個別の高さでばらつく。`'expected'`/`'max'` 選択時は左のカバー率バーが単調減少、右の属性値バーがばらつく。
- 棒下ラベル（属性値の万表記 / 最大・期待カバー率% / コンボ数・確率）は現状踏襲。
- 脚注の「並び順: 〜の降順」表記を、選択キー（属性値由来スコア / 最大カバー率 / 期待カバー率）に応じて表示する。棒の説明にデュアルバー（左カバー率・右属性値）の凡例を加える。

### 4. ページ説明文（`index.astro`）

判定縮小タブの並びを「属性値由来スコア順（カバー率でも並べ替え可）」へ更新する。

## 影響範囲とデータフロー

- `compareShrinkBy` は純粋関数。`baseScore` / `maxCoverSec` / `expectedCoverSec` はいずれも `buildCardStrengthEntry` で選択曲ごとに算出済みのため、曲・特効・ブローチの変化に追従する。
- 属性値バーの相対正規化に使う「最大 `baseScore`」は、現在表示中の縮小エントリ集合（フィルタ適用後）の最大値とする。`ShrinkChart` 側で算出する。
- `CardCompare.svelte` の `shrinkSort` state の型と初期値を更新する。

## テスト

- 単体テスト `tests/unit/score/cardStrength.test.ts`:
  - `compareShrinkBy('attr')`: `baseScore` 降順で並ぶこと / `baseScore` 同値なら期待カバー率降順でタイブレークすること
  - 既存の `'expected'` / `'max'` のタイブレーク（`baseScore`）は維持されること（回帰防止）
- E2E `tests/card-compare.test.ts`:
  - 縮小ソートセレクタに3つの選択肢があり初期値が属性値由来スコアであること
  - 属性値バー（デュアルバーの右側）が描画されること（`data-testid` を付与して検証）

## エラー処理

- 既存挙動を踏襲。`songDuration` が 0/不明ならカバー率は `-`。表示中エントリの最大 `baseScore` が 0 の場合は属性値バーを高さ 0 として扱う。

## 検討した代替案

- **属性値由来スコアを主キーに一本化（ドロップダウン廃止）** — カバー率での並べ替えも残したいというニーズがあるため、ドロップダウンに選択肢追加する方式に変更。
- **属性値由来スコアを主キーに固定し、カバー率はタイブレークのみ** — 同上の理由で、切替式の方が柔軟。
- **属性値バーをカバー率と同じ絶対軸で描く** — カバー率（率）と属性値スコア（点）は単位が異なり共有軸にできないため、属性値バーは相対正規化とした。
- **デュアルバーにせず属性値はラベルのみ** — 「カバー率の横に属性値を視覚的に並べたい」という要望に応えるためデュアルバーを採用。
